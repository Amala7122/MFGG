# 可赋予的环境破坏

破坏是一项物件能力。攻击提供范围和破坏强度，组件处理碰撞、模型切换和碎片；攻击不判断物件是石块、小树还是矮墙。

给现有物件根节点添加一个 `Node3D` 子节点，挂载 `res://scripts/destructible_component.gd`，选择 `Profile`。根节点保留原模型和 `StaticBody3D` 碰撞，也可以包含多个静态碰撞体。组件自动计算模型边界，登记所有子碰撞；完整模型不必使用专用脚本。模型 / 碰撞应在组件进入场景树前准备好。

推荐场景结构：

```text
物件根节点（Node3D 或 StaticBody3D）
├─ Intact（完整模型，可以是导入的模型场景）
├─ 原来的静态碰撞（可有多个）
├─ Rubble（可选：树桩、残墙等破坏后模型，无阻挡碰撞）
└─ Destructible（Node3D + destructible_component.gd）
```

默认 `Object Path` 指向组件父节点，`Intact Path` 指向 `../Intact`，`Remains Path` 指向 `../Rubble`；可以在检查器中改成已有节点路径。没有 Intact 时自动隐藏物件内的几何节点；没有 Rubble 时只产生动态碎片。物件碰撞使用环境层（第 1 层），才能参与当前攻击、落点和地面检查。

同一预制场景的所有实例都继承这项能力，关卡摆放无需逐个写逻辑。不同外形可以共享 `stone.tres` 或 `wood.tres`；需要新表现时复制材质配置，调整强度、碎片网格 / 材质 / 颜色、尺寸比例、数量、飞散速度、寿命和尘土。木材默认为 0.5 级，石材为 1 级。共享配置不保存某个实例是否已经破坏。

物件类型不需要代码分支；每种外形仍需要模型和碰撞资产。树桩、断墙等特定残骸由 Rubble 提供；动态碎片使用配置中的网格，缺省为低多边形块。这是完整 / 破坏两态加预制碎片表现，不进行任意网格实时切割，也没有环境血条。

现成示例：`prototypes/combat/spatial/props/small_tree.tscn` 和 `low_wall.tscn`。两者只有场景资产及同一个组件，没有各自的破坏脚本。`destructible_prop.gd` 只保留石块 / 残柱的程序化示例外形，内部也赋予相同组件；新增物件无需继续扩展它的 kind。

泰坦参数页的「环境破坏」可以分别调整砸地、横扫、跃击和跳跃普攻的破坏强度，默认均为 1；设为 0 关闭对应攻击的破坏。防御护盾没有攻击范围。地面技能提前显示破坏后的可达范围，破坏发生在实际命中时：砸地先破坏再结算伤害；横扫随手臂推进；跃击在下落接触及落地冲击时处理；跳跃普攻在挥击窗口内处理，不创建地面效果。普通墙和强度不足的物件仍会遮挡。

碎片只负责表现，不阻挡角色、不造成伤害。每组 1–32 块，全场最多 8 组，默认 4 秒清理；暂停冻结。组件发出 `broken` / `restored` 信号供关卡更新导航，`reset_destruction()` 恢复原碰撞层和模型可见性。Spatial Lab 已接导航更新、F5 重开和清空；正式关卡仍需在自己的生命周期中接入这些信号和恢复操作。
