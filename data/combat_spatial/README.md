# 可赋予的战斗空间能力

给 CharacterBody3D 根节点的 `Combat Spatial Profile` 赋予资源，或在建立 NavSteering 前设置 `combat_spatial_profile` 元数据。新敌人复用同一资源与控制器；通行策略不读取物种 ID、名称或 Boss 标签。

现有组合：`ground.tres` 行走；`jump.tres` 行走 + 跳越；`jump_break.tres` 行走 + 跳越 + 破障；`climb.tres` 行走 + 攀附；`air.tres` 持续飞行。运行时复制资源，从 `parameter_bindings` 读取角色实际运动参数、破坏强度与冷却；不修改共享模板。绑定后禁用的能力不参加规划。

`preserve_ground_style` 默认开启：同层、直视、没有危险下降或脱困任务时，保留角色自己的绕行、后退与选招。能力演示关闭此项，完全使用公共接战路线。无论谁决定水平移动，危险边界都经过出口验证。

## 角色接口

通过 `steering.spatial.bind(values, callbacks)` 提供真实接口：

| 接口 | 返回 / 行为 |
| --- | --- |
| `can_attack()` | 当前姿态能够执行的真实攻击；不能只按水平距离停步。 |
| `attack_pose(Transform3D)` | 候选姿态是否能攻击目标；不能启动动作、改变角色位置或生成显示网格。 |
| `remaining(channel)` | 角色技能的真实剩余冷却。 |
| `consume(channel, seconds)` | 将通行动作的消耗同步到角色既有冷却。 |
| `break_action(component, point, ability)` | 发动物件攻击，命中时按正常破坏接口结算；前摇期间碰撞保留。 |
| `attached_action(delta)` | 在实际附着姿态且攻击成立时执行受支持的攻击。 |

`cooldown_channel` 关联通行与攻击技能。入坑后 `permits_channel(channel)` 禁止攻击占用唯一返程冷却；现有跳跃角色已接入。新有限次数、体力或潜地能力需要通用执行器实现真实资源扣除 / 预留，不能只添加能力标记。

## 物理和策略

行走使用实际碰撞烘焙的导航，逐段验证地板、完整身体与头顶。跳越验证起跳、整个弧线、完整脚印和下降后的出口，用正常碰撞与重力移动。薄板坡仍保留挡脚边，由既有 0.3m 跨坎能力通过。

破障只预测具体物件与足够强度的真实动作；未击破前不能通行。破坏 / 恢复使路线失效并合并导航重烘焙。攻击玩家的候选检查当前真实遮挡，合法破障则可以先攻击物件。

主动下降前证明能从预计落点返回原安全支撑。入口消耗计入返程冷却，等待不能超过 `max_escape_wait`；坑内预留出口。玩家真正离坑后优先返程，回到安全支撑才释放预留。强制掉落保留真实物理后果，从已知上层支撑重验出口，不瞬移或刷新技能。

坑内追击走到墙边后，可先行走到已验证的起跳位置再返程。原入口被玩家占用时，在同层附近验证另一处真实出口；落点不与运动模式会碰撞的角色重叠。泰坦的实际 `leap_max_elevation` 默认 6m，攻击跃击和公共跳越 / 脱困共用此值及原 7s 冷却，所以可以进出主场 5m 坑；调低能力后同样拒绝入坑。

无法下坑时，坑沿本身就是掩体：从当前支撑层查找完整脚印能站稳的边缘，只沿边缘最多 3m 或后退最多 1.75m 选择站位；搜索锚点固定，不随每次搜索向外漂移。使用玩家实际相机、枪口与射程检查身体遮挡，盲区内停留 1.5–3s。默认每个停留窗口结束有 15% 概率短暂进入射界，停留 1.2s 后退回；无合法暴露位置时保留盲区，探头也不允许跌入无出口的坑。上述半径、停留和概率属于 `CombatSpatialProfile`，可以跨物种调整。没有安全点时报告仍暴露。未来可穿透掩体、移动掩体需扩展威胁模型。

持续飞行角色复用 `air_combat_steering.gd`：赋予 FLY 能力，绑定实际速度与可选 `attack_pose(Transform3D)`。相对目标和真实地板求飞行高度，无世界 Y=0 下限；按完整身体净空及真实攻击发射口检查缩小盘旋圈。遇到坑壁时验证先上升 / 进入目标上空 / 下降的路线，实际碰撞移动；攻击和俯冲恢复后仍回到可接战空域。蜂的模型、晶针与俯冲只提供角色适配，策略不读取物种 ID。此局部空域策略尚未自动搜索复杂迷宫里的完整三维路线。

追击与撤离共用 **2.2ms 目标预算**，分帧轮询、有限搜索与弱引用清理。单次引擎查询不能中途抢占，所以这不是绝对帧上限。路线候选不生成地面效果，已有刷面预算独立保留。

## 墙面 / 天花板连接

在场景添加 `SpatialTraversalLink`（`scripts/spatial_traversal_link.gd`），配置能力 ID、局部 `points` 与 `normals`，可设双向与启用状态。点是身体中心路径，法向指向身体离开接触面的方向；墙顶转角必须留出身体转动空间。

共用执行器检查平移 / 旋转、连续接触与最大转角，实际改变身体姿态和支撑方向，通过碰撞移动。元数据 `spatial_attachable=false` 禁止附着；接触面消失后真实下落。必须走到连接起点，不允许远处吸附。倒挂到玩家上方仍要满足角色攻击姿态接口。

目前使用场景作者提供的通用连接，未自动生成整关墙顶导航。演示已验证真实爬墙、转到天花板攻击与失去附着后的下落。未来蜘蛛复用此能力 / 连接 / 策略，另适配自己的攻击表现。

`FLY` 支持经验证的空域连接；`CUSTOM` 通过 `TraversalCapability` 的 `plan_custom / begin_custom / step_custom / cancel_custom` 扩展，默认拒绝。潜地介质与出土执行器尚未实现；泰坦的出生出土动画不算脱困能力。

演示：`res://prototypes/combat/spatial/capability_lab.tscn`；真实敌人投放：同目录 `combat_spatial_lab.tscn`。行为测试：`tests/test_combat_spatial_capabilities.gd`、`test_combat_spatial_policy.gd`。
