# Automated tests

`tests/` 只放可以明确给出通过 / 失败结果的自动检查。

当前测试：

- `test_combat_reactions.gd`：真实泰坦跃击的撤离成功 / 来不及、泥偶硬吃 / 晶兽击退 / 蜂坠地与起飞、致死不恢复、跨物种赋予、实墙 / 高度 / 悬崖出口、取消 / 暂停 / 清空、玩家推力打断撤离与 Boss 击杀归属。使用 `--fixed-fps 60`；带图形运行加 `--capture-reactions` 保存实际画面。

- `test_environment_destruction.gd`：真实泰坦砸地破坏小树 / 长矮墙边缘、横扫按进度破坏、跃击的下落接触破坏与落地震碎、跳跃普攻空中破坏且无地面效果；任意模型 / 多子碰撞赋予及原层恢复、木材配置复用、300 件密集破坏不截断、强度 0 关闭破坏、实墙遮挡 / 范围外 / 强度不足、一次伤害、取消 / 暂停 / 寿命 / 数量上限、导航更新与清空 / 重开恢复。使用 `--fixed-fps 60`；带图形运行加 `--capture-destruction` 保存前后画面。

- `test_combat_feedback.gd`：无敌模拟承伤、护盾倍率/溢出/回复、受击与翻滚免伤、实际/模拟混合口径，以及真实晶兽飞扑；矩形、圆形、扇形和胶囊预警在坡道、台阶、平台、掩体与悬崖上的刷面，覆盖与命中一致、遮挡 / 断层 / 孤立墙顶排除、飞扑障碍截断、横扫笔迹、普通攻击无地面效果，追踪锁定及炮击闪光复用。建议 `--fixed-fps 60`；带图形运行加 `--capture-feedback` 保存地表预警和统计页截图。
- `test_attack_surface_performance.gd`：平地横扫 / 飞扑的完整范围构建预算、横扫全程网格复用及逐帧成本、三个并发坡面追踪的共用帧预算与最终锁定精度。使用 `--fixed-fps 60`。带图形运行的 `test_combat_feedback.gd` 另检查横扫在 0 / 40 / 100% 时的实际像素，未扫区域不能提前显示。
- `test_player_hitscan.gd`：T02 相机瞄准与枪口阻挡，覆盖贴脸、相机横向偏移、穿入掩体、掩体角、伤害结算、爆头、狙击穿透与射程。

- `test_combat_spatial_lab.gd`：小空间场实际碰撞、导航烘焙、默认整组投放、九个玩家起点、B 循环补兵与原 Combat Lab 默认值。
- `test_combat_spatial_navigation.gd`：泥偶、晶兽、泰坦共十二次实际薄板坡上下行；低坎可跨、高挡边及低顶不可跨。使用 `--fixed-fps 60`。
- `test_combat_spatial_attacks.gd`：晶兽和泰坦从远处接近小台面，跳跃普攻命中一次后落回原地、无技能地面效果；完整落脚检查、大平台真实跃击、过高台面与低顶拒绝。使用 `--fixed-fps 60`；带图形运行加 `--capture-spatial-attacks` 保存命中与跃击截图。
- `test_combat_spatial_policy.gd`：默认 AI 在 2m、5m 有坡平台建立真实命中；不能脱困的小怪长期守住坑沿盲区，概率 0 / 1 验证短暂探头后退回；Boss 下 5m 坑攻击并在玩家占原入口时跳回附近；蜂追到坑上方真实晶针 / 俯冲命中。保留玩家碰撞与 SpringArm。使用 `--fixed-fps 60`；`-- --cliff-only` 只跑悬崖，`--debug-t03` 输出站位 / 返程 / 空域诊断。

- `test_stability_contracts.gd`：核心运行契约，例如画质档位、坠落处理、击杀归属、目标相机等。
- `test_lowpoly_mesh.gd`：低多边形倒角网格的绕序、法线、尺寸与碰撞生成。
- `test_runtime_world_visibility.gd`：正式主场景运行时的关键世界节点可见性，以及帧率 / VSync 基线。
- `test_procedural_clouds.gd`：两套云形的网格复用、封闭连续表面、高低差、分层风速、循环边界、云影开关/状态恢复、编辑器适配和六模型陈列。可 headless 运行；带图形运行时另检查实际 MultiMesh 提交。
- `test_cloud_shadow_rendering.gd`：必须带图形运行；检查高空单层、双层重合、交错的实际阴影像素，完整遮光核心不能重复变暗或漏光。对照图与检查数据写入项目同级 `visual_captures/cloud_shadow_layers/`。

约定：

1. 自动测试必须通过退出码表达成功或失败。
2. 只打印观察数据、需要人工判断的脚本不要放在这里。
3. 一次性或手动诊断脚本放在 `tools/probes/`。
4. 已不存在的历史测试名不要继续写进“当前自动检查”清单。
