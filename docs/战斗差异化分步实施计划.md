# 战斗差异化分步实施计划

更新：2026-09-27。来源：[敌人技能与玩家战斗改造讨论稿](敌人技能与玩家战斗改造讨论稿.md)、[敌人 juice 差异化方案](敌人juice差异化方案.md)。

用户已要求分步实施，优先步态。第 1、2 步首版已完成并验证，接下来推进第 3 步；表中的候选规则沿用讨论稿，数值仍是原型起点。不要一轮同时重写全部兵种和玩家技能。

## 顺序与交付

| 步骤 | 改造内容 | 可单独试玩的结果 | 当前状态 |
|---|---|---|---|
| 准备 | 独立战斗测试场，复选兵种与数量、倒数、暂停、重开、A / B 循环与数值统计 | 可查看实际武器数值、输出 / 承压 / 资源及按兵种对比的封闭空场 | 已完成 |
| 1 | 步态与移动身份 | 轻快、普通、重装、远程四类持续可见的行动区别 | 首版已完成并验证 |
| 2 | 基础攻击时序与共用预警 | 准备 → 锁定 → 出手 → 收招；动作、预警与实际命中一致 | 首版已完成并验证，包含三种新原型 |
| 3 | 玩家近战替换手雷 + 小型追猎者扑击 | E 定向扫击，击退小怪并打断扑击准备，Q 暂留救急 | 待实施 |
| 4 | 巨型破坏者红轨冲锋 | 蓄力、宽轨迹与箭头、锁向直冲、撞墙停止、冲空收招 | 待实施 |
| 5 | 敌方狙击手 + 玩家单发激光 | 红线锁定可以躲，青白激光穿透清楚且止于掩体 | 待实施 |
| 6 | 地面持续危险与其他招牌技能 | 先一种旋涡，再分小批扩展重锤、盾击、连斩、突刺、招架等 | 待实施 |
| 7 | 受击/死亡/声音差异与混合战斗调校 | 加强脆、快、重、稳等身份，复杂敌群仍能读清威胁 | 待实施 |

## 第 1 步：优先步态

战斗测试场基础统计已完成，操作与口径见 [战斗测试场数值统计建议](战斗测试场数值统计建议.md)。步态与攻击时序首版均已完成并验证，下一项为第 3 步“小怪与玩家形成应对关系”。

不等新技能，也不依赖换模型：先用现有两套骨架实现四种运动身份，并允许图鉴条目少量覆盖。

| 类别 | 覆盖兵种 | 观察重点 |
|---|---|---|
| 轻快 | 小型追猎者、迅捷刀手、疾行刺客、猎杀幼体 | 低伏、短快步、膝部弯曲明显，起步和刹停快；身体高频起伏保持克制 |
| 普通 | 近战士兵、狂战士、精英剑士 | 直立、协调摆臂、自然肩胯运动；狂战士更大幅前倾挥臂，精英更稳 |
| 重装 | 重装战士、大型盾卫、巨型破坏者 | 低步频、较宽步幅、缓慢移重，慢起步和转向、收脚较慢；盾卫摆臂更小 |
| 远程 | 侦察射手、点射游骑兵、旋流术士、弹墙炮手、重型迫击炮 | 面向玩家横移/后退有对应摆腿，躯干与武器更稳，蓄力和连发时收脚；重炮换位更沉 |

实现范围：

- 实际位移驱动步态；速度、体型和步幅共同影响步频。堵墙、腾空和被击退时不继续假跑步。
- 正常速度也能体现前倾，起步、停步有平滑过渡；受击偏移不累积。
- 前进、后退、横移使用相应腿部方向，保留已有抓枪 IK 和近战挥击。
- 起步、刹停和转向随预设变化；现有单个兵种的重量属性覆盖继续优先生效。
- 不增加本轮新技能，不调整血量、伤害、护甲、击退抗性或最高移速。

参数入口：`data/game_config.json` 中 `enemy_gaits` 保存四个预设；`enemy_roster.entries[].gait_preset` 选择预设，`gait` 覆盖少数姿态或行动参数。转向/起停的合并顺序为默认重量属性 → 步态预设及覆盖 → 兵种显式 `attrs`。

验收：不同颜色和名字不能成为唯一线索。对照小型追猎者、近战士兵、巨型破坏者、侦察射手的接近、换向与停步；再检查远程横移/后退、击退与受阻。比较 30/60/120 帧下的步态节奏，重跑导航与战斗测试场检查。

第一版是风格化程序步态，不包含逐脚锁地或坡面足部 IK；这些可在步态身份确定后改善，避免过早绑定未定型模型。

首版验证记录：四类步态覆盖全部 15 个图鉴条目；预设/个体覆盖互不污染；前后横移、停步、腾空、真实击退、起步及转向差异、射手蓄力站定后恢复换位检查通过。30/60/120 帧步频一致。原有导航起点/坡面/绕障/站定回归、稳定性检查与战斗测试场检查通过；另保存了灰色、隐藏名字、无 HUD 的四类动作对照图。

验收脚本：`tests/test_enemy_gaits.gd`、`tests/test_enemy_motion.gd`、`tests/test_stability_contracts.gd`、`tests/test_combat_lab.gd`。步态数值仍可根据试玩继续调校；测试场的纯净战斗界面保持不变。

## 第 2 步：命中与预警先对齐

抽出准备、锁定、出手、恢复和取消的公共约定；先用普通士兵与现有迫击炮验证。普通近战从“攻击开始立即扣血”改到清楚的命中帧，复核距离、朝向和遮挡。预警不造成伤害，攻击区与预警区一致。

验收：躲过出手阶段便不受该次伤害；取消、死亡和重开不残留预警或延迟伤害。条带、扇形、圆圈、红线可按后续实际技能逐个补齐，不先建复杂的技能编辑器。

### 第 2 步首版交付（2026-09-27）

`scripts/enemy_attack_area.gd` 提供准备、锁定、一次冲击、恢复、取消的公共约定。扇形、长条、圆圈和飞扑走廊使用同一份世界坐标范围快照绘制预警与判定命中，预警顶点投射实际碰撞地面。完整危险边界从第一帧显示，内部红色填充随倒计时逐渐扩大：圆圈/扇形由中心向外扩张，砸地长条/飞扑走廊向前铺满；锁定后颜色加深。填满时对应挥击命中、炮弹落地或晶兽起跳，暂停冻结填充，取消立即清除。普通近战与傀儡/泰坦在真实挥击帧隐藏预警并结算一次，晶兽的走廊保留到命中或落地。

| 敌人 | 本步行为 |
|---|---|
| 正式图鉴的普通近战及其变体 | 抬臂只预警；动作进度 32% 锁定、62% 挥下命中，两个进度与骨架共用常量；复核扇形、距离、高度与掩体，收招期间不追击或补扣血 |
| 巨型破坏者的现有挥击 | 旧的隐性贴身秒伤并入可见挥击，附加量为 `contact_damage × attack_interval`；持续命中时保留原有贴身压力，闪避成功则不额外受伤 |
| 泥土傀儡（新原型） | 前方挥拳扇形预警，沿用独立的前摇/挥拳/后摇调参；射击或击退按原有规则打断后立即撤销旧攻击 |
| 沉积泰坦（新原型） | 直线砸地和扇形横扫共用范围判定；保留泥盾、狂暴、攻击倍率与恢复节奏；狂暴转阶段继续取消旧蓄力，下次攻击重新显示扩大后的预警 |
| 迅捷晶兽（新原型） | 显示飞扑走廊；前 65% 蓄力跟踪，最后 35% 提前锁向，起跳后不再修正；实际扫过身体的线段在走廊内判定，一次飞扑仅命中一次，碰墙/落地/被打断收招 |
| 现有射手和迫击炮 | 全局攻击排队移到准备前；最后 35% 蓄力锁定方向/预测落点，枪口光变亮；点射的一组连发不再逐发追瞄，打断会撤销未发出的连发 |
| 迫击炮落点 | 第一帧显示完整圆圈边界，不再缩放半径造成误读；弹体与落点使用同一物理时钟，圈内多人各结算一次，实体掩体和高度限制继续生效；射手死亡或攻击取消会撤销尚未落地的炮击及其弹体 |

普通挥击的全扇形角度入口为 `data/game_config.json → enemy.melee_attack_angle`（首版 110°）。三种新原型的距离、角度、伤害和动作时长仍取各自 JSON/本轮调参快照；群体预约依然发生在预警开始之前。晶兽走廊展示本次飞扑的最大可达区域，伤害需要身体实际经过，碰墙或提前命中可缩短位移。

所有预警都只是提示；取消/死亡/重开不会触发旧的延时伤害，暂停也冻结动作与炮击倒计时。已发出的普通弹丸继续沿原有轨迹与寿命运行。本轮保留测试场的武器数值和统计界面，没有新增覆盖战斗画面的面板。

验证记录：攻击时序专项覆盖普通挥击 30/60/120 积分步、实际物理帧命中、锁定后闪避、重复冲击、掩体/高度、多人炮击、暂停及死亡/重开清理；三种原型、独立调参、群体运动、步态/绕障、A/B 循环、数值统计与稳定性回归通过。倒计时 25% / 75% 对照图保存于 `visual_captures/step2_attack_countdown_25.png`、`visual_captures/step2_attack_countdown_75.png`。坡面预警使用碰撞地面投射，复杂地形与大量重叠预警的最终可读性仍随后续技能和混合实战继续调校。

主要验收入口：`tests/test_enemy_attack_timing.gd`；原型回归：`tests/test_mud_golem.gd`、`tests/test_sediment_titan.gd`、`tests/test_fast_beast.gd`、`tests/test_enemy_tuning.gd`、`tests/test_enemy_crowd.gd`。运行时指定 `--headless --fixed-fps 60`，保证以帧数计时的验证与动作的物理时间一致。视觉对照入口为 `tests/capture_enemy_attack_timing.gd`。

## 第 3 步：小怪与玩家形成应对关系

沿用讨论稿首版建议：E 前方扫击，频繁使用且需要朝向；Q 保留现有全周脉冲。小怪明显退开并中断可打断的扑击准备，普通怪弱击退，重怪局部受击；击退遇墙缩短，不穿墙命中。退出手雷正式操作，并处理正式界面的名称、提示和冷却。

小型追猎者先做“接近 → 收身 → 锁向短扑 → 落地恢复”。验收扫击能创造射击空间，多目标只各命中一次，多怪同时命中时不叠加过强镜头震动。不默认小怪全部一击必杀，不默认挥击期间无敌。

## 第 4 步：巨怪冲锋

实现宽红轨迹和箭头，前段缓慢跟随，末段锁定，再直线冲锋；每目标每次只结算一次冲锋伤害，受实体障碍和可通行地面约束。横移能躲，冲空或撞墙留出反击窗口。首版不附带持续裂地伤害，也不默认激光可以打断巨怪。

验收平地单只 → 多只与小怪混合 → 正式场地坡面和障碍。导航追击不能改写已锁定的冲锋方向。

## 第 5 步：两种射线各自读得清楚

先以点射游骑兵为狙击手候选：站定、红线追踪、锁线、单发、装填；红线和实际判定被遮挡点截断，最后锁线后横移有效。玩家狙击先保留现有单发、弹药与穿透规则，改为青白脉冲激光表现；光束视觉停留不重复造成伤害。

验收锁线可躲、不能穿掩体，激光终点与伤害射线一致，逐个穿透反馈清楚。持续激光是独立后续选择，本步骤不顺带改成持续伤害。

## 第 6 步：一类地面危险，其他技能分小批

先做旋流术士的单种持续地面旋涡，清楚区分预警与激活；是否减速另外验证。随后按基础能力分批：扇形攻击（刀手/重锤/盾击）→ 推进与位移（狂战士/刺客/幼体）→ 防御与封路（盾卫减伤/剑士招架/炮手危险带/连续炮击）。每批控制在 2–3 种，使用讨论稿第 8 节作为候选表，不一次定死全部 15 项。

验收混合敌群中的可读性，限制同时出现的高威胁锁定；技能排队在预警前进行。坡面、草地、天气与掩体下继续核对预警和伤害范围。

## 第 7 步：反馈与整体节奏

在步态和技能身份稳定后，为轻、快、重、远程配置受击形变、死亡收尾、音色和强度。小怪脆、重怪稳、射手枪身反馈清楚；反馈不得遮住预警，不通过高频抖动体现重量。

最后验证组合压力、击退距离、反击窗口与玩家技能冷却；检查敌人死亡、暂停、取消和重开清理，以及正式波次计数。正式 HUD 的重做独立安排，战斗测试场仍保持纯净战斗画面。
