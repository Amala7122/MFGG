## 技术方案

### 已核实的接入点

| 目标 | 文件与位置 |
|---|---|
| `enemy_shot` 音效 | `scripts/ranged_enemy.gd` 的 `fire_pattern()`（约 311 行）—— 五种弹幕模式的唯一分发入口，一次齐射响一次；定位用 `muzzle.global_position` |
| `explosion` 音效 | `scripts/grenade.gd` 的 `explode()`（约 101 行） |
| `shockwave` 音效 | `scripts/shockwave.gd` 的 `perform()`（约 23 行） |
| 敌人子弹生成 | `scripts/ranged_enemy.gd` 的 `spawn_enemy_bullet()`（约 373 行）—— 所有弹幕的唯一出口 |

音频调用约定沿用既有写法（`audio_manager.gd` 是 autoload 但刻意无 `class_name`，避免与 autoload 名冲突）：

```gdscript
const AudioUtil := preload("res://scripts/audio_manager.gd")
AudioUtil.play_at("enemy_shot", muzzle.global_position, -6.0)
```

`instance` 为 null 时全部静默降级，不影响任何现有逻辑。

### 对象池扩展（本批的主要设计点）

`scripts/object_pool.gd` 现有工厂签名是**按 GDScript 类**新建对象，而子弹是 `PackedScene` 实例化的，两者不能共用。方案是新增一个并列入口，释放路径保持共用：

```gdscript
static func acquire(key: String, script_class: GDScript) -> Node      # 既有，用于 ImpactSpark / DamageNumber
static func acquire_scene(key: String, scene: PackedScene) -> Node    # 新增，池空时 scene.instantiate()
static func release(key: String, node: Node) -> void                  # 既有，两者共用
```

选择新增并列函数而不是把参数改成 `Variant`，是为了保持类型明确、避免运行期类型判断。

### `enemy_bullet.gd` 池化要点

该节点是场景（子节点 `$Core` `$Aura` `$Trail` `$Glow`），`setup()` 已经集中重置了 direction / shooter / fired_by_player / damage / speed / turn_rate / 颜色，但池化后仍有三处必须处理：

1. **`pulse_time` 未重置** —— 脉冲相位会带到下一次，`$Aura` 的缩放会跳变；需在 `setup()` 中归零
2. **`apply_color()` 每次都 duplicate 三个材质** —— 这会在池化之后成为主要剩余开销；需缓存上一次的颜色，颜色未变则跳过
3. **两处 `queue_free()`**（命中约 74 行、超时约 79 行）改为 `ObjectPool.release(KEY, self)`

调用顺序无需改动：`ranged_enemy.gd` 已是「先 `global_position` 再 `setup()`」，`setup()` 内部负责 `look_at`。

### 导航边角修法预判

若探针确认该敌人是生成在了不可导航的位置（离网格距离明显偏大，例如掩体顶面或树冠内），修法是在落点计算之后加一步吸附：

```gdscript
NavigationServer3D.map_get_closest_point(get_world_3d().navigation_map, candidate)
```

落点计算分布在 `scripts/enemy_spawn_point.gd` 的 `choose_random_spawn_transform()` 与 `scripts/survival_director.gd` 的 `choose_spawn_position()`。若探针显示该敌人离网格很近、只是路径查询瞬时失败，则不改代码，只在 `nav_steering.gd` 的注释中记录该现象。

### 执行约束（硬性）

- **所有 Godot 进程调用必须带 120 秒硬超时**，并在超时后强制终止；结尾追加兜底清理，逐个用命令行校验（含 `--headless`）后才杀。**绝不终止编辑器进程**（命令行含 `--editor` 且无 `--headless`）。
- 临时探针以 `_xxx.gd` 命名放在项目根，任务结束必须删除。
- 本项目惯例是**用代码构建节点**，不手写 `.tscn`，本批不引入新的 `.tscn`。
- 场景流程按 4.23 场景 3：独立 GDScript 直接读写；本批不涉及节点/场景结构变更，因此不需要 `build_godot_scene`。

### 校验方式

- 单脚本语法：`Godot_v4.7.1-stable_win64_console.exe --headless --path <proj> --check-only --script res://scripts/x.gd`，输出含 `Failed to load` 即失败
- 运行时冒烟：`--headless --path <proj> --quit-after N`，过滤 `SCRIPT ERROR|Parse Error|Invalid call|Invalid get|Node not found|null instance`
- 状态探针：`extends SceneTree`，注意 `child` 为 Variant 时 `var x := child.foo()` 会报「Cannot infer the type」，需显式标注类型
