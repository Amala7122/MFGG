# 战斗测试场数值统计建议

更新：2026-09-27。适用场景：`res://prototypes/combat/combat_lab.tscn`。

基础统计已于 2026-09-27 实施。左上角显示当前武器等级、威力、射速、模块加成、弹匣与狙击数值，全部读取实际武器。暂停面板的测试等级仍是下一次生成设置。

暂停后点击“查看战斗统计”，查看本次条件、有效伤害 / DPS、各来源输出、命中率 / 爆头率、兵种击杀效率、承压与恢复、资源、A 每批 / B 滚动统计，以及升级 / 模式变化分段。战斗实时简洁统计可选，默认关闭；结果自动打开统计页。具体操作见 [战斗测试场说明](../prototypes/README.md)。

下文保留设计口径；中位数 / 慢端用时、专项追击 / 卡住分析、未实施技能的专项统计，以及 CSV / JSON 导出仍属后续内容。当前实测均速包含攻击站定、击退等状态，不能当成纯追击速度。

## 先回答什么问题

测试数据应帮助判断：武器是否打得动、哪个兵种带来的压力最大、弹药是否支持持续战斗，以及新技能是否创造了预期的应对机会。只显示总伤害或一串配置参数，很难解释战斗为什么舒服或难受。

建议第一版做六组数据，详细内容放在暂停和结果面板，避免数字抢走观察动作的注意力。

| 第一版统计 | 显示内容 | 用来判断 |
|---|---|---|
| 本次测试条件 | 当前武器等级与升级模块、敌人测试等级、兵种与数量、循环模式、是否无敌 | 两次测试是否能够直接比较 |
| 输出效率 | 有效总伤害、近 5 秒 DPS、全程平均 DPS；主射击 / 狙击 / E / Q 分开 | 输出低是武器弱、打空，还是没有射击机会 |
| 击杀效率 | 总击杀；各兵种击杀数、平均击杀用时、平均击杀耗弹 | 哪些怪太肉，哪些怪缺少威胁 |
| 射击效果 | 命中率、爆头率；不同武器分别统计 | 差别来自伤害配置还是瞄准与命中难度 |
| 玩家承压 | 生命损失、护盾损失、受击次数、破盾次数；按敌人种类拆分 | 哪些敌人真正造成压力，伤害是否过于集中 |
| 资源与节奏 | 实际耗弹、拾取补给、换弹次数 / 时间占比；A 每批用时，B 近 30 秒击杀率 | 是否存在输出断档，持续战斗能否维持 |

场面摘要再补上存活总数 / 各兵种数量、玩家当前生命与护盾。它们放在暂停页，便于解释刚才那一段战斗。第一版不需要给每只怪增加永久数值标签。

## 显示方式

- **默认战斗画面**：保留当前武器等级、准星与短暂命中反馈，维持现在的简洁程度。
- **可选实时统计开关**：以后提供一块固定位置的小面板，只显示近 5 秒 DPS、近 30 秒击杀数、近 5 秒生命 / 护盾损失；默认关闭。与等级读数留出间距，不覆盖准星或预警。
- **暂停面板**：将“配置”和“统计”做成互斥页签，避免在现有配置旁再挤一列。统计页上方是本次条件和汇总，下方是可滚动的兵种表、伤害来源表。暂停时读数冻结。
- **单轮结果**：复用统计页并附上胜负与用时。A / B 持续模式通过暂停查看，玩家倒下时保留最终报告。

兵种表建议列：兵种、存活 / 击杀、敌人最大生命 / 护甲、击杀用时、击杀耗弹、对玩家的受击次数与生命 / 护盾损失。移速和攻击间隔作为展开详情，避免表格太宽。敌人参数读取本次生成后的实际值，不能直接拿图鉴基础值代替。

## 统计口径必须明确

### 伤害和 DPS

有效伤害取每次结算前后的实际生命减少量，并将剩余生命下限视为 0，排除过量击杀伤害。例如敌人剩余 10 点生命，一枪结算 100 点，有效伤害是 10；过量的 90 可以留到后续调校页单独看。

护甲、弱点和其他减免以最终结算为准。一个穿透射击命中多个敌人，可以累加各目标有效伤害；同一目标不能因光束视觉停留重复记账。环境死亡单列，不能算成武器输出。

近 5 秒 DPS = 最近 5 秒的有效伤害 / 有效窗口时长，开战不足 5 秒时用已发生的战斗时间。全程平均 DPS = 有效伤害 / 全部有效战斗时间，包含接近、躲避与换弹，反映实战效率。只有正在开火时计算的 DPS 若以后增加，必须另标“开火期间 DPS”。理论伤害 / 射速只做参考，不能当成实测 DPS。

### 击杀用时与命中

- 击杀用时（TTK）：某只敌人第一次受到玩家有效伤害到死亡的时间。一击击杀记 0 秒，并同时显示击杀耗弹。混合武器击杀标为混合，不能全部归给最后一发。
- 生成到首次受伤的时间另称“接战等待”，生成到死亡的时间另称“在场时间”。对面墙的距离、导航和步态都会影响它们，不能把这些时间混成武器击杀用时。
- 初版显示样本数与平均值，后续样本充足再补中位数和慢端用时。没有击杀样本显示“—”，不能显示 0 秒造成误解。
- 命中率：至少命中一个有效敌人的射击次数 / 实际射击次数。一次扳机的多弹丸和穿透共享射击编号，命中多个目标仍只算一次命中的射击，比例不会超过 100%。
- 爆头率：有效爆头命中次数 / 支持爆头判定的有效命中次数。它与按射击次数计算的命中率分开标注。

### 玩家受伤与无敌

生命损失和护盾损失分别累计，不直接相加冒充一种伤害。当前小型近战对护盾有独立倍率，同样的原始伤害对两者影响不同。回血、回盾、拾取恢复另计，不能用“开局生命减当前生命”推算累计受伤。

无敌开启时显示明确标记，实际生命 / 护盾损失为 0。若需要比较怪物命中压力，可以另记“被无敌拦截的攻击尝试及原始伤害”，但这不是实际承伤，也不等价于关闭无敌后的伤害：受击无敌窗口、破盾和死亡都会改变后续战斗。冲刺免伤、重复碰撞等被拒绝的判定也不能算成真实受击。

每次有效受伤要携带敌人类型与攻击类型，才能区分普通攻击、冲锋、狙击和地面效果。仅凭来源坐标无法可靠归属到某种敌人。

### 弹药、时间和重开

耗弹按实际射击消耗累计；拾取补给、换弹、备用弹药转移另记，不能用弹药库存的净变化代替耗弹。每杀耗弹按武器分别显示，E / Q 参与击杀时说明其贡献，避免把低耗弹全部解释为枪械增强。

首次倒数结束开始计时，暂停与倒数不计入；玩家生命归零停止承压与战斗计时，死亡演出不追加战斗时间。手动生成开始一次新测试并清零本次统计。自动补兵保持统计连续，清空结束统计，可保留上一份报告供查看。

## A / B 模式分别看什么

| 模式 | 主要比较 | 需要注意 |
|---|---|---|
| 关闭循环 | 全灭时间、各兵种 TTK、承伤、总耗弹 | 适合小规模对比武器、单种敌人与技能 |
| A：全灭后补整批 | 本批 / 上一批用时，累计批数；每批承伤、耗弹和换弹时间 | 玩家位置与资源不重置；每批的接敌路程可能不同，不能认为相同阵容就等于完全相同条件 |
| B：逐只立即补兵 | 近 30 秒击杀数 / 每分钟击杀率、输出与承伤、耗弹和补给变化 | 没有“全灭时间”；刚开场敌人尚未接近，预热阶段与持续交战阶段分开比较 |

玩家拾取升级后，当前武器可能变强，但自动补兵仍使用本轮开始时的敌人测试等级。报告保存等级与模块的变化时点，输出效率按变化前后分段；不能混成一个平均值后拿去判断同等级平衡。中途切换 A / B 也要标记并分段。

## 配合当前步态，以及后续技能

现在优先验证步态身份，除上述统计外，可在兵种详情加入追击时的实际水平速度、接近到攻击距离的时间、卡住时间，以及进入近身范围的次数。先限定有追击目标且允许移动的状态，避免把蓄力站定、死亡和击退误报为卡住。实际速度必须读取真实位移，不能只显示配置移速。

这些数据能帮助区分“动作看起来重”“移动确实慢”“转向或导航有问题”；动作辨识度仍要靠观察，不能仅由速度数字代替。

新技能落地时再增加对应统计：

| 后续改造 | 最有用的专项统计 |
|---|---|
| E 近战与小怪扑击 | 每次命中数量、打断次数、实际击退距离、扑击完成 / 命中次数 |
| 巨怪冲锋 | 发动 / 取消 / 命中次数、撞墙次数、收招窗口内受到的反击伤害 |
| 敌方狙击与玩家激光 | 锁定完成到命中的比例、激光每发命中目标数、各目标有效伤害 |
| 地面持续效果 | 玩家进入危险区次数、实际停留时间、触发伤害次数与生命 / 护盾损失 |

命中率分母排除出手前取消的技能，取消另列。击退看实际距离，撞墙导致短距离是正常结果。预警出现但没有伤害，可能是成功躲避、被打断、受遮挡或目标不在范围内，不能一律算成“躲避成功”。

## 建议分步实现

1. 已完成：当前武器完整数值显示，含等级、威力、射速、强化和弹匣。
2. 已完成：本次条件、有效伤害 / DPS、击杀、生命 / 护盾损失与恢复、暂停统计页及可选实时统计。
3. 已完成：射击编号 / 命中去重、按兵种 TTK / 耗弹 / 受击来源、无敌拦截、资源、A 每批 / B 滚动统计与等级 / 模式分段。
4. 待后续技能落地：加入专项指标；有长期调参需求再增加 CSV / JSON 导出。

实现入口以真实伤害结算、实际射击与死亡事件为准。`EventBus.hit_confirmed(headshot, killed)` 继续只负责命中反馈；`scripts/combat_telemetry.gd` 提供可选观察入口，只有测试场实例携带记录器。`prototypes/combat_lab_stats.gd` 保存累计、窗口和分段数据，`combat_lab_stats_view.gd` 呈现报告，不从血条、音效或命中提示反推数字。

验收脚本：`tests/test_combat_lab_stats.gd`，并回归战斗测试场、A / B 循环和正式稳定性检查。实际射线射击、近战、弹幕、炮击、手雷和脉冲均已覆盖。
