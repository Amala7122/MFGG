## 定位结论

已复现与用户截图相同的密集表面纹路。直接触发环节是太阳 PCSS 软阴影的采样伪影：云影功能扩大了同一太阳的阴影深度与软阴影角径，影响到了地面、道路、石柱等所有接收太阳阴影的物体。本轮确认参数组合的因果关系；未检查引擎内部 shader / GPU 驱动，不能把具体底层算法错误进一步认定为某个引擎或驱动 bug。

17.4 时基线实际值：阴影深度 3000、角径 1.446013689°、Bias 0.1、Normal Bias 0.15。正午基线为深度 702.917、角径 0.5°，同机位的道路没有傍晚那种密集纹路。

| 单一变量对照 | 实际结果 |
|---|---|
| 保留云体，仅取消其投影 | 纹路仍在；道路与墙面局部像素指标与基线相同 |
| 关闭 SSAO | 纹路仍在 |
| 关闭全部太阳阴影 | 纹路消失 |
| 保留阴影、角径降到 0（关闭 PCSS） | 密集纹路消失，近景物体投影仍保留 |
| 保留 PCSS、深度降到 20 | 纹路明显减少，但仍有少量采样颗粒，不能据此宣布修好 |
| Bias 或 Normal Bias 分别加到 1 | 无明显改善 |
| 隐藏所有旧云入口 | 纹路不变；本次基线旧背景云节点数已为 0，SkyDome 的旧 cumulus / cirrus 均为 false |

固定道路 ROI（860,980）～（950,1060）的相邻像素亮度平均差：基线 6.5725、仅关闭云投影 6.5725、关闭 PCSS 0.0088、深度 20 为 1.3839。该指标是描述性对照，非视觉验收标准。

用户关于新旧云同时出现的反馈保留为 I-045；本次固定状态没有复现两套旧云同时启用，不能据此否定其他天气 / 场景状态存在混用。旧实现代码确实保留，但 `backdrop_landmark.gd` 在发现新云场时跳过旧背景云创建，共享环境关闭旧 Sky3D 云层，WeatherSystem 还会显式关闭旧 cumulus。

修正方向：需要同时处理 `cloud_lighting.gd` 的运行时扩深 / PCSS 逻辑和 `hyrule_field.tscn:94` 已保存的 702.917 深度。仅在场景 Inspector 降深度会被运行时再次覆盖；仅关闭云投影也不会恢复近景阴影采样。直接关闭 PCSS 能规避纹路，但会改变高空云影柔度，因此本轮没有把诊断参数保存为正式修复。

按需查阅当前 Sky3D shader 与 Godot 4.7 的天空灯光实现，并以 `surface_pattern_diagnosis.gd --overcast-sky` 隔离。曾实验显式传入太阳 / 月亮方向，未改善发黑，相关实验改动全部撤销。`cloud_layer_diagnosis/20261009_010139_d333d163/` 导入访问冲突失败；`cloud_layer_diagnosis/20261009_010306_e2e7c6cb/` 四组真实图形对照通过：恢复 mie 强度没有改善，只恢复大气白昼 / 地平线调色即可显示天空。

根因：现有大气散射先乘 `atm_day_tint`，随后再乘白昼 / 地平线调色；原阴天目标颜色约 0.27～0.39，两个 `source_color` 转换并相乘后重复压暗。原模糊云幕曾遮住这个效果。现在共享 `cloud_lighting.gd` 的阴天颜色（白昼 0.78/0.83/0.89，地平线 0.78/0.80/0.83），运行时雨控制与编辑器预览复用，未增加天空叠层。
