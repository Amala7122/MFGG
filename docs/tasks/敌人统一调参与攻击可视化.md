## 判断基线

- 最终目标：换敌人仍能按同一概念调参，体型与实际攻击匹配，范围／轨迹可见。
- 硬约束：预览与真实战斗同源；保存候选／默认分开；保留已保存方案；自动运行使用隔离启动器。
- 待验证假设：基础体型没有同步所有关联设置。根节点已有缩放不能证明世界空间查询也已缩放。
- 候选：仅改原 JSON 标签（无法约束后续敌人）；改全部存储键并迁移方案（迁移面与回归成本大）；共享语义适配表＋原存储键（推荐，统一界面与合同并兼容方案）。实际映射必须逐项核对，不把不同冷却语义强并。

### 核实原因与方案选择

- 实际`charge_speed`旧上限30，控件、草稿和存储均使用它；50在运行技能之前就被输入校验挡住。真实兜虫冲锋代码没有30的速度钳制。
- 提交失败设置的消息会被`_on_session_changed`用通常为空的草稿验证结果覆盖；观察动作另有静默拒绝路径；返回也经过同一提交门禁，形成“按钮坏了”的体验。
- 图形检查还发现原生SpinBox在聚焦／格式化时把1001显示为1000，即使内部已保留原文，仍会误导用户。
- 比较三个候选：仅提高兜虫上限（遗漏其他字段和失败链路）；取消一切边界（比例、正时长、整数槽位和逐帧取样仍有真实约束）；统一范围元数据＋分层校验（采用）。旧min／max作为原建议，实验支持边界另列，默认value与方案保持原样。

1. `enemy_parameter_limits.gd`统一七份schema的实验范围，690个数字字段全部有约束说明，654项边界放宽，其余保留颜色／角度／固定槽位／囊体收缩等有效约束；42个开关不改。速度0–1000米／秒、距离上限1000、通常时长300秒、预计算飞行时长30秒、频率通常100Hz、生命／伤害10亿、通常倍率／权重100、体型20。具体边界仍以字段提示为准，已有合法范围不缩窄。
