# 泥土傀儡重建：大量炮灰（结构实验）

状态：**独立研究分支，不合并。2026-10-23 已完成可运行化（编译、开局预热、受击闪光测试、无头测试）并做 30/100 只 A/B；30 只约 -1%、100 只约 -10%，不能视为“已经解决30敌人卡顿”。**

这是可推倒重来的学习项目，不把旧敌人的节点组织当成不可变前提；但保留战斗**事实**的正确性，尤其是攻击排队、拳击时序、有效命中和死亡结算。

## 设计判断

一只傀儡需要自己的生命、位置、碰撞体、独立出拳/受击时序，而不需要自己拥有6个 MeshInstance3D、独立的 StandardMaterial3D、可选却无实际预警的 AttackArea 绘制树和始终可见的文字。

过去100实体消融测试（见 [百体敌人架构设计](../features/百体敌人架构设计.md)）已证明完整呈现仍占显著预算，但未将它与 CPU 脚本/渲染调用精确拆分。本重构是用于独立验证的**结构假设**，不引用尚不存在的新测试成绩。

## 已更改的实体职责

| 职责 | 旧实现 | 本分支 |
|---|---|---|
| 生命、受伤、独立位置与碰撞 | 每只 CharacterBody3D | **保持每只真实 CharacterBody3D** |
| 目标、寻路、空间能力、群体避让 | 每只 NavSteering/CombatSpatialController/Crowd | **原逻辑保留**，不得用上轮失败的walk-only替代 |
| 普通拳头的攻击范围和命中 | 每只 EnemyAttackArea：Node3D+2 MeshInstance3D，即使没有地面提示 | `MudGolemMelee`：RefCounted，无单体绘制或物理 tick；攻击状态、扇形/遮挡、Tween前摇/锁定/命中时间保留 |
| 泥土身体模型 | 每只建Mesh/Material与6个MeshInstance3D | 场景共享4个 Mesh 和4套实例材质，按24m网格划分批次，用4个 MultiMeshInstance3D/占用网格提交躯干、晶核、双拳、双腿 |
| 动画姿态 | 每个网格自身挂在对应部件节点 | 每只只留视觉根、躯干、左右手臂、左右腿和晶核的**纯节点姿态锚点**；新渲染器每个显示帧读取变换，保持个体步态和攻击Tween |
| 受击闪光 | 每只HitFlash节点+覆盖材质 | MultiMesh INSTANCE_CUSTOM 颜色通道，单个伤害计时值，独立闪光 |
| 死亡散架 | 从各自MeshInstance重挂到六个物理碎片 | 临死查询当前真实姿态和**共享**Mesh/Material，此时才创建六个物理碎片，保持物理散落和生命周期通知 |
| 头顶文字 | 持续可见 | 默认只在受伤后显示约1.5秒（`always_show_health_label`可配置） |
| 攻击观察工作台 | 从右手的子网格读取位置 | 从**实际渲染同一姿态的右拳锚点**读取；死亡当帧仍不报告已消失部件 |

## 这里还没有解决的问题

- 复杂 `CombatSpatialController` 仍可能是稳态成本大头，它的寻路/逃逸和近距离攻击约束暂未删；上一轮删掉它导致傀儡围住玩家不攻击，这次严禁重复。
- MultiMesh 无逐实例视锥剔除。按24m网格切分，可改善远距离不可见群体的浪费，但同格内离屏实例仍一起绘制；一格至少4个绘制组。单场景有多少格由测试报告给出。
- 一屏极多傀儡时，渲染器按每个显示帧为每只上传6组姿态（4种 Mesh）。它不是零开销；若成为新瓶颈，可进一步改成渲染线程批量buffer或GPU动画，而不是盲目加层缓存。
- 首次创建 shader/批次是否触发冷编译尖峰、全场景和复杂地形是否始终不误剔除，必须图形环境验证。
- 当前没有完成完整关卡、100个真实敌人60FPS 或“视觉完全无差异”的承诺。

## 真实工程验收

### 1. 自动回归（必须从隔离副本运行）

```powershell
python tools/run_acceptance.py --tests test_mud_golem_architecture test_creature_navigation_and_attacks test_enemy_attack_queue test_attack_observer_lifecycle test_enemy_parameter_contract --task mud-horde-contracts
```

该命令会自动执行 Godot import、引擎错误门槛和脚本；报告位于独立的 `_artifacts` 目录。新测试断言 **14只独立傀儡、4绘制组、按位置换区、全部6个死亡碎片可生成、真实拳击扇形可达性与原 AttackArea 的169个位置采样相等、拳击只能结算一次、移除后不泄露注册**。如出现任一错误，应停止性能测试，不把出错版本当作优化成果。

### 2. 固定种群的真实运行对照

本分支提供：

```powershell
python tools/run_probe.py tools/probes/mud_golem_horde_perf.gd --graphics --realtime --task mud_horde_30 --args --count=30 --warmup=120 --frames=450
python tools/run_probe.py tools/probes/mud_golem_horde_perf.gd --graphics --realtime --task mud_horde_100 --args --count=100 --warmup=180 --frames=600
```

比较原开发快照时，可用旧版已有的 `burst_crawler_perf.gd`（`--species=mud_golem --count=30`，当时数量入口上限为40），使用**相同正式场景/分辨率/画质、同机器、热缓存和真实时间步进**。100只只能在本分支新入口测试；不能将它直接与之前不同比例100只混合兵种比较。

A/B 必报真实在场数、平均FPS、P95/P99（新探针旧的frame_stats只含P95，正式用户试玩另需逐帧日志）、绘制调用、节点数、攻击次数及视觉截图。若导航行为或动画不同，暂停发布收益判断。

### 3. 实战试玩（最终条件）

先30只，再100只，玩家真实移动/躲避，查看：追击可持续、角落绕路不僵住、围住玩家仍能申请并完成挥拳、攻击有前摇/有效方向/单次结算、受击闪光和死亡碎片可见。帧率期望至少稳定60FPS；当前**没有取得该成绩**。
