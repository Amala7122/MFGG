# T00：基线与隔离验证

> 本文件是 [测试台体系摸底与规划](../实验与调试体系摸底.md) 的分片。
> 批次状态、依赖与验收门槛以主文件的批次表为准；本文件只保存该部分的调研／规划原文。


- **范围**：记录代码与实际方案、当前测试条件；以沉积泰坦作为建议试点，保留现有玩法和用户参数。它已有战斗、正式直战、外形展示和技能几何，可覆盖主要风险。若核对后当前技能不适合采样，明确选择另一项已有技能，不新增或恢复旧招式。
- **新增基线**：把 `sanctum_main` 的 encounter 路由、30／45／60 人数及容量、CreatureCatalog 与旧图鉴身份分开记录。确认当前 Deployment 的随机 2–4 只批次没有持久编组语义，为“单成员组兼容→固定编组”的 A/B 明确比较条件；不直接以 A×8 替换正式数量。
- **已有证据与待做**：本次交接／观察覆盖／入口专项可作为开工参考，正式开工时确认源码指纹；六小怪和 Boss 的首次接入不再作为新功能开发。继续核对正式 Boss 指定方案、独立死亡／毒池、旧实验入口保留用途；候选预览的全局状态／物理隔离仍需单独测量。
- **最小验证**：同一条件分别运行当前切场景重建方式和“保留现场＋一个隔离预览”的候选。核对现场位置、血盾、技能状态、随机状态与进度；同时确认预览中的实际技能／物理可运行，输入与慢放不影响原现场。
- **证据与判定**：记录打开／返回耗时、内存及状态差异。推荐候选必须保留预期现场状态；若分组、autoload、物理或共享资源发生串扰，先限定会话作用域，未解决前不铺开后续架构。不能只凭子视口画面不同就判隔离成功。
- **改动入口**：现有视觉测试台的全局慢放、GameFlow、Arena／RunState、Boss／陪练启动、Graphics／WorldBackdrop 等。诊断放 `tools/probes/`，证据放独立产物运行。此批不建设完整工作区、不迁移全部参数。
- **自动运行约束**：遵守 [AGENTS.md](../../../AGENTS.md) 的鼠标与焦点隔离要求，经统一启动器执行；T00 还要核对 MouseControl 的请求状态和真实系统状态，并处理将用入口仍直接读写 Input 的缺口（I-266）。不能用用户鼠标试验捕获或直接运行原工程取代隔离验证。

## T00 执行结果：研究完成、自动验证通过（2026-10-20）

**目标／约束**：验证原现场可保留、真实技能／物理可预览，同时识别全局串扰；保持当前正式参数与编排。硬约束是编辑器工作中心、显式保存、固定条件可复查和自动运行不抢鼠标；“单个独立 World3D 足以隔离”只是待验证假设，本轮已否定。用户只授权本批，T01 不自动开工。

**已交付入口**：新增 [testing_session_probe.gd](../../../tools/probes/testing_session_probe.gd)，通过 `python -B tools/run_probe.py tools/probes/testing_session_probe.gd --task testing_session` 复查；加 `--graphics` 保存真实预警。固定波次／个体种子与当前正式泰坦快照，在新圣所实际生成 Boss，检查 31 项状态字段（含完整参数、位置／速度、血盾、技能／Tween、冷却、波次／随机状态、关卡进度、刚体和节点 Timer）。源玩家保留正常物理处理，再由会话暂停隔离；不是预先关闭玩家来冒充输入隔离。

本批新增的是一个研究探针，`tools/probes/` 原始 GDScript 计数由前次复核的 62 增为 63；不新增独立测试台场景，已登记的 12 个开发场景入口保持不变。

| 对照路线 | 实测结果 | 判断 |
|---|---|---|
| 保留现有重建流程 | 加载同一主场景／玩家会产生新实例，完整原状态未序列化；无头约 2.51 秒、图形约 5.91 秒 | 可保留为“重新挑战”，不能宣称原帧继续；不作为跨台返回默认 |
| 裸 SubViewport＋独立 World3D | 全树目标查询选中源玩家，Resource 与 RunState 共享；总暂停下刚体不模拟 | 排除为完整隔离方案，不能只加一个视口就铺开 |
| 受控同进程：源节点／物理空间冻结，组／限流缓存隔离，Resource 复制 | 真实震拳造成一次预览伤害、刚体落下，输入与慢放不改检查字段；完整播放与中途取消均无源节点残留。但全局下一随机数已改变 | 有限采样技术可行；完整战斗隔离不通过，I-271／I-272 保留，不以“状态表没变”掩盖随机串扰 |
| 保留源现场＋独立进程实际技能／强制终止 | 子进程使用相同快照，实际技能一次命中；刻意改 RunState、Arena、慢放、随机数、Resource 和输入，父现场及后续随机数均保持，取消后无残留子进程 | 在本次真实技能范围内通过；推荐完整战斗预览沿此执行边界推进 |

**成本与边界**：图形父进程下，受控同进程打开约 30 ms、返回约 3.5–3.7 ms、增加约 2.6–3.1 MiB 引擎静态分配；独立预览启动到技能完成约 2.33 秒，中止约 2.11 秒，子进程约 112.25 MiB 引擎静态分配。子进程本次始终无头；重建计时包含地图／Boss 准备，独立进程计时包含完整技能，两者工作量不同，不能据此比较速度优劣。样本受加载顺序／缓存影响，不是产品启动预算、总进程 RSS、显存、FPS 或长期性能结论。

**明确推荐**：主工作区保留现场与参数界面；完整 AI／物理预览优先独立执行，经过核验的纯采样才留在主进程。以临时会话快照／草稿传递参数，正式保存仍单独确认；不先重构所有敌人／地图以支持同进程多世界。独立预览的窗口交接和通信仍有成本，后续 T01 定合同、T03／T04 接入时核验，不把本轮的子进程研究接口当作成品。

**必要修正**：[战斗原型场](../../../prototypes/combat_lab/combat_lab.gd) 的七处鼠标读写改用 MouseControl，并将该目录加入 [鼠标隔离守卫](../../../tests/test_mouse_control.gd)，补上 I-266。游戏玩法、敌人参数、命名方案、波次数量／权重未改；当前按个体预算和随机 2–4 只批次的模型仍保留，未开始编组迁移。
