# 布局要求与全局调节入口

> 本文件是 [测试台体系摸底与规划](../实验与调试体系摸底.md) 的分片。
> 批次状态、依赖与验收门槛以主文件的批次表为准；本文件只保存该部分的调研／规划原文。

## 所有测试台／调试面板的布局要求

2026-10-20 用户明确：**清晰、信息密度高，字体可以适当小，不需要讲究配色。** 此要求覆盖四个核心测试台及画面、天气、玩家、声音、导航等测试调试面板；属于每批的实现／验收要求，不留到 T12 做装饰性统一。

- 优先使用紧凑表格／网格、短标签、对齐数值与明确单位。减少大标题、卡片、留白和重复说明；不以装饰配色作为交付目标，状态依靠文字／符号即可识别，颜色只可辅助。
- 常驻标题、状态、选中数量优先合并为一行；操作用短标签排成紧凑工具栏，不做通栏大按钮、不为完整句子单独占多行。长说明、完整动作范围和被省略的文字用鼠标悬停浮动提示；关键未保存／生效范围仍在常驻短状态中可见。
- 常用调试文字以11–12逻辑像素、按钮约20–24逻辑像素高为起点，按实际字体和缩放核对可读性；不靠放大整个控件补偿长文案。空反馈不留高度，非空反馈一行摘要＋悬停全文；狭窄窗口允许必要换行，但不得重新挤掉主体内容。
- 布局验收记录标题／操作栏和主体列表／参数区的实际高度；当前配置页在支持的窗口与UI缩放下，应把大部分垂直空间交给敌人列表。其他模块按内容制定空间预算，不能只验证按钮可见而不检查常驻信息占比。
- 按对象／模块分组，常用值直接可见，高级项合理折叠，支持搜索定位；保持高密度同时可读，不把全部字段混在一页，也不把每个字段拆成需要反复开关的大面板。
- 字号允许小，在用户常用窗口／UI 缩放下检查可读性；不为视觉美观放大。验收检查文字／输入值／单位不重叠、不裁切，保存、未保存、生效方式与报错能找到。
- 四台、其参数页和观察预览共用左上角导航位置与返回组件；观察工具条避让导航条。返回不再分散在底部操作区、观察工具条末尾或其他局部角落，详见“[四台编辑归属与统一返回](#四台编辑归属与统一返回)”。此为待实施要求，不将当前不同位置的按钮记为已统一。
- 数字精度按实际 schema 保留，不把未编辑字段取整回写；可直接键入，支持常规键盘切换与提交。界面只在明确需要时重建控件，避免输入焦点丢失。
- 关卡／波次主表明确列“编组、份数（组）、每组人数（只）、总人数（只／只读）、投放时序”；容量面板显示“人数硬上限、目标线、存活／预留人数、排队组数”。组数和人数不得混用一个无单位的“数量”。
- 面板标题或常驻状态行清楚显示当前场景／对象、编辑的包／编组／波次、正式／测试作用范围和草稿状态；截图与用户实际操作共同验收，不能仅凭控件存在认定清晰。

## 跨测试台全局调节入口（2026-10-20 用户补充，待实施）

用户明确要求全盘考虑画面风格、Sky3D、天气等公共调节，所有测试台都能直接进入，不要求先启动某个专用场景。此要求是整合主线的横向约束，纳入B-020；本轮只补规划，当前仍在修复T01列表入口，不提前实施后续批次。

**全局入口判定规则**：不依赖某个敌人／编组，调整当前场景整体表现或公共运行条件的功能，默认进入公共目录；对象专属参数保留对象入口并可从目录定位。新增功能必须登记“公共／对象／场景限定”及可用入口，不能再只新增配置或快捷键。

**入口与值的范围分开**：每个可交互测试台都有固定位置的“全局调节”入口、相同模块目录与搜索，兼容现有快捷键。打开后直接作用于当前测试上下文，不切场景、不重开游戏、不依赖玩家生成或正在战斗。全局可达不等于写全局数值：明确显示当前场景、共享包／本场景差异／本轮草稿；个人显示与音量设置另属个人保存范围。敌人、技能、编组等对象参数仍从对应对象进入，公共目录提供定位与关联跳转。

| 公共调节域 | 全局目录中的模块与作用 | 接入批次与边界 |
|---|---|---|
| 显示与渲染 | 分辨率、窗口模式、UI缩放、3D渲染比例、已支持的质量／阴影选项；显示实际生效方式 | T04先直达既有显示入口，T08完善作用域。个人设置不保存成关卡环境包；不虚构未实现质量开关 |
| 画面风格与后处理 | 正式手绘／滤镜、灰模、已支持的曝光／色调等；原画对照和恢复 | T04先直达既有F9／F10并解除无玩家／已暂停的误拦截，T08接共享包和场景差异。风格画布的实验材质仍标实验专用，未适配正式渲染前不冒充同一效果 |
| Sky3D与日月时钟 | 天空、大气、太阳／月亮、昼夜时间、时间推进与固定时刻 | T09a接公共模块，任何测试台能定位当前天空来源、参数与启用状态；不要求去天空专用场景才能调整 |
| 云层 | 云形／层／覆盖、移动、透光和云影；固定种子、暂停时间、重播观察 | T09b接同一运行实现与参数包，明确天空云显示与投射地面云影的差别 |
| 天气与风 | 天气类型、雨雪、风向／风速、过渡／时间线及当前实际读到的天气参数 | T09c接公共模块，指定天气／种子可复现；先显示控制来源与过渡状态，不让天气调度器立即覆盖手动草稿 |
| 光照与环境 | 主光、环境光、雾、局部环境、已支持的阴影／反射等；显示天气／时间／场景谁在驱动 | T08建立场景环境适配与来源，T09与天空／天气驱动衔接；关闭天空／天气仍保留室内光照和独立雾，不造第二套抢写同一属性的控制器 |
| 声音 | 总／分类音量与试听、现有合成音调音器／音色参数及命名方案入口 | T10b接公共目录；个人音量、共享音色配方与本轮试听分开，未开发音色能力明确保留 |
| 公共运行与观察 | 暂停／继续、既有慢放与相机观察选项、固定条件／种子、重跑与捕获入口 | T04统一暂停与输入合同，T06接场景测试条件，T10接记录／诊断；当前运行与下次重开生效分开，不靠重设全局随机数伪造现场恢复，不要求另开发通用相机系统 |
| 性能与公共诊断 | 帧率／渲染与系统开销读数、已有记录／捕获／导航诊断入口，说明运行条件 | T10c／T10d按能力接入；独立性能测量不在编辑面板常驻运行；仅特定场景可执行的诊断说明条件，不静默重建现场 |

**当前断点已核对**：`PostProcess`及`GreyboxDirector`虽是autoload并创建F9／F10面板，但`sketch_panel._can_open()`要求存在可控制的玩家，`greybox_panel.open()`拒绝已暂停场景；视觉台可能无玩家，战斗台配置时已暂停。因此“已经autoload／存在快捷键”不是全局可用，更不是可发现的显式入口。登记I-282，后续在公共上下文中接入，不能通过先开战再调画面绕过。

**公共上下文与关闭合同**：入口记录场景、模块实际目标、启用状态、来源、草稿和原暂停／鼠标状态；统一模态仲裁、输入优先级与Esc返回。测试台配置、统计、数值输入和独立预览中均可达；关闭后回原面板／原暂停状态，不擅自继续战斗或丢草稿。独立预览按T00隔离边界传递允许的快照，不把父子进程全局节点当成同一个控制器。

**场景适配与启停**：所有测试台都展示同一公共目录；绑定当前场景已存在的天空／天气／光照，说明真实有效状态。未启用时仍能查看／编辑所选包；需要临时挂载的兼容场景提供明确启用／恢复动作，不自动塞入天空或开始下雨。当前场景确实不适用／暂缺适配要说明原因和计划，不能只放灰按钮就标“全接入”。地下／室内按模块独立关闭，不连带关掉后处理、音量或室内光照。

**逐批门槛**：T04交付公共入口和既有画面／灰模／显示模块直达，T08落实环境包与作用域，T09接天空／云／天气与对应光照驱动，T10补声音和诊断；不等到T12才添加入口。每接一个模块就登记入口、当前场景适配、单位／范围、生效方式、重播与保存；新增测试台同步接入。T12统一覆盖守卫按当前有效入口登记表逐一运行，当前12个只是摸底快照，不把固定计数当长期唯一清单。

**验收必须走真实入口**：逐台直接F6，从可见“全局调节”打开模块，不先运行另一个测试台；覆盖无玩家、准备／暂停、战斗中、原模块正在编辑、独立预览和返回场景。检查当前场景立刻观察、固定条件重播、保存重开、取消／恢复、快捷键不冲突，以及共享包与场景差异不误写。无天空／天气的室内夹具验证入口仍可达、模块可关闭、室内光照／后处理保持；不要求新建地下关卡。菜单可见、快捷键触发、实际可调整和效果生效分别验证。
