## 2026-10-21 视觉与战斗参数职责分离讨论

用户询问两台重复调参时配置不同如何处理，提出视觉台只处理外形和看动作。关联I-313／B-020。首轮完成代码核对、职责建议与实施顺序记录；用户随后已认可职责分离方向，并要求四台统一归属与返回，现行补充见“[四台编辑归属与统一返回](#四台编辑归属与统一返回)”。尚未实施UI过滤、配置迁移或新批次开发，仍按逐批指令开工。

**当前事实**

- `visual_model_panel.gd._build_fields`与`combat_lab/enemy_tuning_panel.gd._build_fields`均读取`Layout.groups(profile, Tuning.get_schema(profile))`，所以同一敌人的完整定义在两个界面重复开放；目前没有字段编辑归属过滤。视觉台可编辑的是3个纯外形条目，其余已登记战斗条目仍以观察为主。
- 二者调用同一`Session.shared`／`open_profile`／`set_value`／`save_as`，读取同一`data/enemies`定义及`data/enemy_presets/<profile>.json`命名方案。共享草稿身份包含profile、preset、target，同一进程内相同身份同步；保存候选与active分开，覆盖已有方案前检查磁盘指纹。现有覆盖合同不等于操作系统级并发文件锁。
- 分别F6启动属于独立进程，未保存草稿不会互通；已打开窗口也有方案缓存，外部保存后须重读磁盘或重开，战斗实例仍须重建才使用新值。两个入口选择不同方案、未保存草稿或旧实例，会出现不同观察结果；不能宣称现有跨台导航／跨进程实时同步已实现。

**推荐职责**

| 内容 | 编辑归属 | 在另一台中的呈现 |
|---|---|---|
| 轮廓、基础体型、部件尺寸／比例、材质颜色、纯表现姿态／摆幅／步态 | 视觉测试台的外形／动作表现模块 | 战斗台显示当前引用和实际体型，提供“编辑外形”关联入口 |
| 生命护甲、伤害、攻击范围／角度／判定、技能前后摇／冷却、真实移动／冲锋速度／弹道、个体选招策略 | 战斗原型测试台 | 视觉台观看攻击动作时只读相应技能上下文，提供“编辑技能”入口 |
| 姿态选择、播放／冻结／逐帧／慢放、时间定位、机位／观察参考 | 各台自己的观察控制 | 作为本轮工具状态；预览0.25倍速不保存为敌人技能速度或时长 |
| 基础体型、模型部位等会影响碰撞／导航／命中的参数 | 按实际定义确定唯一编辑归属，并显式声明联动；基础体型优先归视觉 | 战斗台可查看缩放后真实几何并验证；修改时正确重建本体／碰撞／导航，不能只更新展示网格 |

视觉台“看动作”包含攻击动作，但技能节奏与实际位移仍由战斗定义驱动。纯动作姿态／摆幅的制作属于表现；出手何时生效、移动多快、判定多大归战斗。后续具体字段必须按真实读取路径确认，不能仅凭名称、旧分页或“专属参数”一键归视觉。

**候选与判断**

1. 保留完整表、增加说明：改动小，仍有大量重复入口和职责记忆成本，不能充分回应反馈。
2. 共用配置／草稿，按字段声明编辑归属，另台只读或调用同一专业编辑器：推荐。保留当前方案兼容性；需要逐字段审查跨域作用，不能简单隐藏几个分页就宣称完成。
3. 立即拆成各台独立配置、方案与保存链路：需迁移现有角色、Boss、编组引用与合成规则；仅按工具分文件还会让技能时序和动作各存一份。当前无必要承担这项迁移；未来独立外形资产／战斗方案可在同一角色装配关系下引用，不作为本轮开工前提。

职责分离仍需便捷入口：在战斗台点“编辑外形”，可以打开视觉专业模块／浮层并携带同一对象、方案、草稿；不要求用户先保存、手动关闭再找场景。正式跨台返回与现场恢复仍属于T04边界，不能将当前建议写成已接通。

**建议实施顺序，尚未开工**

1. T02前置：登记每个字段的唯一编辑模块、纯显示依赖、联动效果与重建要求；保留原存储键。未归属的新字段应触发覆盖检查，不落入任意台的“专属”兜底。
2. 视觉面板仅开放外形／动作表现；战斗面板保留完整战斗编辑能力。共性语义与专业模块内的顺序继续复用，不再要求视觉侧栏列出全部战斗分页。实际未实现的动作编辑能力继续标明。
3. 两边显示相同的对象／方案／未保存状态／生效时机；另台参数只读，编辑动作打开其专业模块。保留统一草稿、校验、错误恢复与候选／覆盖／默认分离。
4. 保存面先继续复用统一草稿与存储，不新增按台复制的整份配置。为后续跨进程往返登记字段／域级修改和来源修订；保存时保留未编辑域，检测同字段冲突，避免旧整包覆盖。具体合并和并发合同需在接入时实测，不宣称当前已有自动合并。
5. T04核对“战斗调技能→编辑外形→返回同一草稿→真实重建／重播→保存→重开一致”。验证纯观察倍速不改技能参数，外形修改不覆盖战斗域，技能修改不覆盖外形域，外部冲突有明确提示。
