## 已确认的交叉项与处理原则

| 实际字段／行为 | 核对结果 | T02处理准备 |
|---|---|---|
| 爬兽`turn_yaw`、`release_snap_ratio` | `crawler_behavior.gd`分别用于真实攻击方向与实际投囊触发时刻；位于“技能姿态”组不代表纯表现 | 战斗原型归属，视觉只读依赖；保留实际时序，不按旧分页整体归视觉 |
| 兜虫`dash_distance` | 纯模型有限展示位移，战斗`_pose`明确清零`visual.rig.position.z` | 与真实`charge_distance`／`charge_speed`分开说明；不能用展示位移证明真实冲锋生效 |
| 爬兽囊体、蜘蛛眼部姿态／位置 | 实际弹体从`sacs[0].global_position`／`focus.global_position`发射，外形调整会改变发射点／遮挡检查 | 仍按外形归属编辑，登记战斗依赖，后续须验真实发射；这也是首批新战斗体先选兜虫的理由 |
| `crowd_*` | 当前`enemy_crowd.gd`以个体／同种邻域响应工作，尚无持久编组策略身份 | 个体反应先归战斗原型；T05组策略另建引用／实例语义，不能把现有全部crowd字段移到空间台冒充完成 |
| 泰坦5项`grenade_*` | 经`get_grenade_resource_config`用于玩家手雷资源 | 登记为玩家／战斗条件模块候选；T02不迁移Boss数据、不删除现有入口，后续接入时明确专业路由和正式引用 |
| `body_size`、模型部件尺寸 | 战斗根节点、碰撞／导航及技能世界值有联动；纯模型与真实宿主应用方式不同 | 唯一基础值，分别声明模型重画／战斗体重建，不仅缩放网格；不能把基础体型重复乘两次 |
| 两面板撤销／重做／还原／保存 | 当前操作整份共享草稿，缩减数值控件并不会自动缩减动作范围 | 同时收紧动作合同，防止视觉模块的“还原”覆盖已调整的战斗字段（I-316） |

职责分离只改变编辑权限／路由，不裁剪共享方案或快照。视觉只读的技能时序仍必须存在于完整草稿供动作使用；不能只把可见视觉字段传给模型导致缺键，也不能在切台时用已保存active替代未保存草稿。

## 首批试点与方案取舍

- 保留三种纯外形现有能力并先做归属收缩、依赖显示与错误恢复；不把只观察的镇墓兽强行接入EnemyTuning，也不恢复用户撤离的大型盾卫。
- **首个新可编辑战斗体选裂甲兜虫**。原计划泰坦为建议试点；当前对比后，泰坦177字段与阶段／保护／手雷／Tween耦合高；只改3个纯外形不能交付战斗宿主外形接入；兜虫已有共享模型与明确`get_body_dimensions(values)`，适合先做可重复的重建闭环。泥偶保留观察，暂不顺带泛化所有旧原型。
- 首组重点验收`body_size`、`shell_width`、`shell_length`、`shell_height`；模型尺寸公式为`(shell_width×0.87, 1.08+shell_height×0.5, shell_length×0.95)`，本次基础值实读`(2.1315, 1.755, 2.6125)`。核对碰撞盒、模型脚底偏移、NavAgent和体型联动；材质及其余已支持外形字段沿同一适配能力登记，不伪造未实现姿态编辑。
- 路线比较：给所有宿主立即热更新需逐类迁移健康／状态机／碰撞／引用，首批代价高；仅换展示网格无法证明真实碰撞一致；**首批兜虫在视觉观察环境用同一草稿显式重建宿主**。保留观察相机／选择／播放状态及草稿，标明样本已重建，不承诺正式现场原帧热更新。T04再接来源实战的安全应用／待重建。
- 兜虫战斗条目仍为play能力，不因可编辑外形就改成scrub；三种纯外形原有采样、部位拾取、慢放和重播保留。

## T02实际开工顺序与改动面

1. **T02.0 归属／导航共同基础**：从候选清单按实际读取确认本批字段，建立唯一专业归属、只读依赖、路由及生效能力登记；复用Layout语义／单位，不复制schema数值。共用返回导航条、调用帧和草稿引用先在视觉／原型页接入；其余台只登记适配点，四台完整互通仍在T04／T06。
2. **T02.1 草稿与动作范围**：会话仍保存完整对象；专业入口只提交归属字段的修改，带来源修订。原文和错误按对象／方案／作用域／专业视图保留。新增模块还原仅修改所属字段，整对象还原单独明确；输入撤回只清本视图原文。共享撤销链保留并记录操作归属，当前模块不得默默回滚另一模块；跨模块最近操作显示归属并通过入口处理，不做跳过中间历史的选择性回滚。保存明确包含同对象各模块已提交草稿，统一校验／冲突保护与候选／默认分离。
3. **T02.2 专业视图**：视觉仅可写外形／表现，技能上下文只读并提供战斗原型入口；战斗原型的外形项显示引用并提供视觉入口。首批涉及的现有公共名称／技能顺序／范围／高精度输入／报错恢复全部保留；未接入路由显示真实状态，不能留无说明的死按钮。
4. **T02.3 兜虫宿主适配**：为观察环境建立模型／宿主能力适配，模型沿用现有apply，战斗体从同一完整草稿在_ready前注入再重建；相机与UI状态单独还原，禁止用`_show_subject`中当前的`Tuning.get_values(active)`和`_reset_view`直接充当通用返回。正式主场景／Boss／编组数据不改。
5. **T02.4 验收与交付**：先过下列回归，再做隔离图形交互／窗口缩放／返回位置验证和功能说明；记录已支持字段／真实生效档位、未支持能力与待用户体验项。按批次结束停止，不自动继续T03。

拟新增归属登记／路由与共用导航组件（具体命名在实施时确定）；需改的真实入口为`enemy_parameter_layout.gd`／`tuning_catalog.gd`／`tuning_session.gd`、两参数面板、`enemy_visual_lab.gd`、`combat_lab.gd`／`attack_observer.gd`以及首批宿主适配。复用`parameter_input.gd`、范围策略、观察相机和现有命名存储。准备阶段这些新运行组件没有创建；AGENTS已对齐“八类语义完整、专业视图按职责开放”，以免旧规则要求每台重复全表。

共用导航调用帧需要区分：来源路由／调用帧、workspace／draft引用、角色／形态与稳定目标、方案及编辑作用域、进入时修订／已采用运行修订、源场景／组／成员／波次上下文、分页／筛选／滚动／相机／观察时间、未提交原文和错误。过程对象引用不直接序列化跨进程；“返回”“接收修改”“实例采用”分别确认。T02验证视图与草稿的导航基础，正式现场冻结和子进程往返仍是T04验收范围。
