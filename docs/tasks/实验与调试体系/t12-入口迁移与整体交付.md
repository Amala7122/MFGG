# T12：入口迁移、覆盖守卫与整体交付

> 本文件是 [测试台体系摸底与规划](../实验与调试体系摸底.md) 的分片。
> 批次状态、依赖与验收门槛以主文件的批次表为准；本文件只保存该部分的调研／规划原文。


- **唯一归属与返回覆盖**：检查每个有效字段是否有唯一专业编辑归属／路由，其他台只读或调用同一编辑器；检查新测试台／参数页／预览是否复用导航条与返回协议，旁路独立返回和本地可写副本均报告缺口。按共同验收矩阵收口，分别记录草稿保留、实例采用、显式保存重开，不以按钮存在或计数变化判整合通过。
- **范围**：完成新旧名称、入口、快捷键、配置绑定与测试守卫的对应；旧可运行场景可保留为明确的兼容预设／转发入口，不重复维护两套实现。未经核对不批量删场景或改全部资源路径。
- **全局入口覆盖**：按公共调节矩阵逐模块／逐有效测试台检查可见入口、快捷键、无玩家／暂停可用、当前场景适配、效果与保存；未启用和未适配分别列出。新测试台或公共参数模块缺入口即报告缺口，不能仅以autoload存在或菜单按钮存在判通过。
- **覆盖检查**：扩展现有入口与敌人观察覆盖守卫，核对注册与真实场景／参数模块／脚本工具的对应；公开配置应登记用途、编辑路由及有效／只读／内部字段，新增有效参数没有模块或保存接口时报告缺口，防止再出现 encounter 这类无入口配置。当前固定“12 个入口”断言按真实迁移调整，不能只改计数。继续保留大型盾卫暂不接入等用户约束。
- **整体验收**：四台往返、真实字段外观／技能反馈、编组份数与波次投放／容量／账目、组身份／策略、关卡正式绑定、跨场景与环境启停、其他工具入口、保存重开及异常路径；全部测试调试面板按清晰／高密度／小字号可读验收。专项通过后按实际改动选择 core／full／图形回归，不每批无差别重跑全部。
- **文档与功能记忆**：同步对应功能说明、原型入口索引和用户指定的 `../项目演进与功能清单.md`；项目外证据含运行条件、配置与源状态。迁移有前后路径、校验与回退记录，不删除未知归属材料。
- **最终状态**：自动通过与用户体验分别记录。用户未确认的观感／手感继续标待体验；已明确保留的未来能力不伪装为本轮完成。
