# T06：可装配场景的实战测试台与四台互通

> 本文件是 [测试台体系摸底与规划](../实验与调试体系摸底.md) 的分片。
> 批次状态、依赖与验收门槛以主文件的批次表为准；本文件只保存该部分的调研／规划原文。


- **四台统一合同**：实战只编辑关卡／波次／组份数等所属层级；组内人数、个体技能和外形全部按归属路由。累计验证四台12种有向跨台往返、三层嵌套与重复进入，覆盖未保存／非法输入、冲突／失败、目标失效、待重建，检查同位置返回及无隐式还原；派生总人数不可作为另一份敌人数量直接编辑。环境和公共条件经同一公共模块进入。
- **T06a 当前关卡显式入口**：实战测试台选新正式圣所后直接定位 `sanctum_creatures` 的编排，能查看／编辑／保存对应的公开字段，区分“编排／波次、投放／容量、角色引用、高级生命周期”。沿当前版本解析，不把只提供文件路径或通用文本编辑器算完成。关卡编辑入口先交付，不等画面／天气等模块全部接完。
- **T06b 编组波次与统一投放计划**：波次编辑使用“编组引用＋份数＋时序”，派生总人数；加入待投组队列、整组准入／容量预留和成员账目。旧单体预算经兼容适配进入同一计划，固定组模式不再叠加种类权重／人数总额。迁移可回退，不未经授权改当前正式数量／权重／节奏。
- **T06c 场景装配与四台往返**：将 Boss 直战／泰坦陪练／通用陪练统一为实战预设与运行功能；优先新正式圣所，再接一个现有战斗测试环境。场景接入声明锚点、导航、环境和生命周期，解除旧 sanctum 限定时保持预检。四台都能携带角色／编组／波次与草稿上下文返回。
- **T06d 正式绑定与记录**：保存命名关卡编排、用于本轮试验、设为正式场景采用三个动作分开；原关卡与测试替换只能有一个投放执行者。报告记录组模板／实例／成员及实际方案指纹，Boss 指定方案不自动改为 active；保留正式掉落、异常恢复、活动死亡演出等待、选卡／结算及取消契约。
- **验收**：用夹具验证 A 的 11×8＝88 和 B 的 20×份数，人数上限 30 时正确排队／预留而不超限或丢成员；超大组、无安全点、生成失败、成员未到齐、异常移除均有明确状态。旧 30／45／60 适配结果与容量／流程对照，不以看门狗强制推进充当闭合；两种环境采用相同方案。新 UI 在用户常用窗口下文字紧凑可读、列单位清楚。
- **边界**：例子不变成正式编排。保留各模式明确入口与迁移证据，不静默删除现文件或恢复旧主场景，不扩大到地图重做、导航算法重构或新敌人行为。
