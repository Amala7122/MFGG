# T05：战斗空间测试台与共享群组

> 本文件是 [测试台体系摸底与规划](../实验与调试体系摸底.md) 的分片。
> 批次状态、依赖与验收门槛以主文件的批次表为准；本文件只保存该部分的调研／规划原文。


- **归属与导航接入**：编组成员／组内数量／组策略由本台编辑；角色外形、个体技能和波次投放通过入口交给对应台。复用同一导航条／调用栈／草稿保留；从实战带组实例／模板修订进入后，返回仍指向原组及原波次。显示成员实际方案与覆盖范围，不在组编辑器复制敌人的整套可写属性。
- **T05a 模板与身份**：在统一角色身份上定义成员／数量／方案／职责、相对队形、投放规则和组策略引用。单成员组可快捷选择；现有固定机制组转为同一数据形式，不要求每组一个文件。复用 CreatureCatalog 接入新六种生物，修通旧 Groups／Scenarios 的身份限制；不能继续仅认 16 项旧图鉴，也不覆盖退役图鉴或新建重复属性表。
- **T05b 编组编辑界面**：战斗空间测试台提供紧凑成员表、组内总人数、角色／属性方案跳转、组策略选择／状态、保存命名方案与重读；组数与人数分别标单位。保留场地／空间能力和便利条件职责。
- **T05c 实例与基础运行**：每次投放产生独立组 ID 与成员归属，模板修订和成员方案在产生实例时锁定；“各自行动”是首个真实兼容策略。队内间隔、生成失败重试和成员死亡都保持组身份，不仅存个数量表后拍平投放。
- **验收**：单成员组、A／B 形式的混合组和重复实例可在界面设计、保存、重开与单组试打；不同实例状态不串。实际总数／成员归属正确，身体空间不足明确报错。测试数据只作夹具，不把用户例子写入正式关卡。
- **范围边界**：具备战斗实现的原型可用于研发，纯外形不能冒充可战斗。高级组策略规则待明确后逐步补；本批不开发全部协同 AI。空间测试台循环中的“成员补位／整组重投”若开放要显式区分，不把无限补兵带进有限波次。
- **改动入口**：`combat_spatial_lab.gd` 的 GROUP_PRESETS、战斗台投放、CreatureCatalog、陪练 Groups／Scenarios 与对应配置；公共编组解析供 T06 使用，避免新增一套只认某个测试台的 ID。
