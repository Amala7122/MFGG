### 本轮执行记录

- 目标：同一圣所暂停现场，分别跑通裂甲兜虫外形链路与沉积泰坦三线重击定格链路；保留A1–A7全部门槛，不宣称单对象全链路或四台全覆盖。
- 开工核对：标题解析确实不支持圣所；GameFlow本身不监听换场景重置状态，但原型台ready／exit会写state，必须把autoload状态随导航帧保存恢复。WaveDirector退出会清空instance／待结算，弹体／闪光退出有清理副作用（I-338）。
- 步骤：风险核对、来源身份／返回与现场隔离、两条应用链路、公共模块均已完成首版；按A1–A7验证后停在等待用户体验，未开始T05及其他覆盖补齐。
- 本轮反馈与范围：只做T04；不补T02的其他宿主、不补T03的其他招式。原有用户未提交文档改动保留，数据schema／命名方案／正式配置未改。

## 一、规划要点（原文保留）

- **统一返回首条闭环**：在T02共用组件上落实来源实例／场景、作用域与修订、嵌套调用栈、父现场冻结、原文回传与真实应用状态。实测“实战→原型→视觉→原型→实战”，返回左上角同位置、回正确调用方且草稿不还原；非法输入也可返回、来源运行值与未应用原因可见；需要重建的明确重建，不把重开场景作为默认返回。
- **范围**：增加最小测试工作区导航，在已有圣所实战中暂停选择试点对象；能带对象和草稿进入视觉测试台、战斗原型测试台，再返回同一个来源现场。选中可由点击／对象列表相互定位，避免身体被遮挡时无入口。
- **交付**：当前对象、实际采用方案、来源场景、未保存状态、生效档位可见；支持当前对象应用与显式同方案多对象应用。往返不要求先保存，也不把保存候选等同修改正式默认。
- **验收**：实际完成“选中→外形编辑→技能形态编辑→返回圣所→继续／重测→保存命名方案→明确选用→重开一致”。外形重建、技能下一次动作与原现场继续分别验证，不把重开冒充原帧恢复。
- **全局入口首版**：所有可交互测试台增加固定“全局调节”，先直接接既有显示、画面风格与灰模入口；修正无玩家、准备／已暂停时的错误门控，不通过先进入另一个场景或先开战取巧。统一菜单、快捷键、模态／输入仲裁与关闭恢复；其余公共模块明确接入批次，不冒充已可调。
- **当前场景合同**：保留原现场的投射物、持续毒池与独立死亡演出状态；本轮预览不能产生正式场景的掉落或推进选卡。已有攻击生成物是否沿用生成时快照、下一次技能何时采用草稿须明确，不能偷偷改写全部存量效果。
- **异常与窗口合同**：实际接入前逐入口核对父现场 Timer／事件订阅；预览取消／退出／失败不得重建原世界、吞掉草稿、改正式进度或遗留子进程。独立预览的窗口／输入交接须由真实图形回归和用户体验分别确认，不能沿用 T00 无头子进程结果直接标产品验收。
- **第一里程碑**：T04 结束应交付一个用户能完整试用的版本；其他敌人／场景／技能尚未支持时单列，不等到全部工具接完才第一次交付。此批先使用已有圣所入口，不提前泛化所有地图。

## 二·补、覆盖限制（2026-10-21 追加，开工必须知道）

T02 可写外形的 profile 只有 3 个（爆囊爬兽／棱眼蛛／裂甲兜虫），T03 可定格编辑的招式只有沉积泰坦的「三线重击」，**两者没有交集**。所以规划原文里「选中→外形编辑→技能形态编辑→返回→继续」的单对象全链路，在当前覆盖下走不通。

本批处理方式（不扩范围、不补覆盖）：

- **子链路 A（外形）**：试点用「裂甲兜虫」——它是唯一同时在画廊有外形原型与战斗实体的对象，能覆盖重建路径。
- **子链路 B（技能定格）**：试点用「沉积泰坦」——只有它的三线重击可定格编辑。
- 两条子链路各自从同一圣所暂停现场进入并返回，分别核对 A1／A3；**不把两条拼成一次「全链路」来宣称完成**。
- 若要求单对象全链路，需先补一处覆盖（泰坦外形可写，或兜虫某招可定格），属补全批次，不在本批范围。

## 七、风险与反例（开工前先确认这些不成立）

1. **切场景与 autoload 耦合**：`_swap()` 会置 `tree.current_scene = null` 并移除来源节点，而 `GameFlow` 是 autoload、暂停面板挂在 root。若 `GameFlow` 在场景切换时重置 `state`，返回会落到 MENU。A2 必须直接断言 `GameFlow.state`。
2. **`workspace_suspended` 只标节点本身**：实战的 `WaveDirector`、定时器、Tween 是否随节点离树真正停住要实测；T00 已证明独立 World3D 不隔离 autoload。
3. **标题解析是第一个必炸点**（`professional_navigation.gd:81`），接入实战先改这里，否则一进就报错。
4. **F10 放宽后**，灰模与显示设置都可能改渲染状态，要测「灰模开→显示设置改→关灰模」顺序。
5. **不要直接删 `_can_open` 里的 `_melee.can_control()`**：它防止调参途中被控，删掉会造成新的手感问题；只加「无 player／暂停」分支。
