# T01：参数归属、草稿与保存合同

> 本文件是 [测试台体系摸底与规划](../实验与调试体系摸底.md) 的分片。
> 批次状态、依赖与验收门槛以主文件的批次表为准；本文件只保存该部分的调研／规划原文。


- **范围**：先完整登记试点字段的对象身份、所属模块、类型／单位／范围、来源、覆盖、应用目标、生效档位和观察方法。其余已发现字段可先标未接入，每批补自己的覆盖，不先手工整理全部字段阻塞可用版本（当前七份 schema 共 732 项，实施时重新核对）。
- **新增合同**：统一桥接 species、属性 profile 与旧图鉴身份；确定编组模板／实例 ID、成员角色、波次组份数与人数派生的区别。把新 encounter 每个公开字段归属到关卡、角色引用、投放或高级模块，不能再次遗漏整份文件的编辑路由。
- **T00 结论约束**：工作区与预览执行不能假定共享全局对象；合同包含会话／对象身份、草稿修订、快照、结果应用／取消和保存范围，允许进程间传递。先定义本批必要合同，不在 T01 建通用远程调用框架或预览窗口；研究工具的临时 JSON 不作为正式配置格式定案。
- **现有来源复用**：新三种的外形／战斗宿主沿用各自 `Visual` profile，不另建重复的战斗属性配置。普通 `@active`、正式 Boss 指定方案、本轮覆盖分别显示实际来源；实例定位同时携带角色身份和预览／战斗形态，不能只靠 profile 选择同名画廊条目。
- **交付**：共享参数与会话入口，复用 EnemyTuning 和现有配置；草稿可撤销／还原，保存命名方案、当前场景选用、项目默认是不同动作。默认另存候选，覆盖已被引用的命名方案时明确影响范围；不能仅靠“不切 active”就认定不会改变正式方案内容。建立方案修订或内容指纹，跨台传引用与草稿而非复制默认值。
- **验收**：选择、修改、保存、重读、切对象／切模块都保持正确；非法值有明确反馈；未保存不写文件；保存失败不丢草稿；保存候选不偷偷变更正式 Boss 指定方案。只为这些实际合同缺口补测试。
- **边界与入口**：适配 `enemy_tuning.gd`、两个现有敌人参数面板与必要保存工具；不一次迁移所有 JSON／Resource，也不把未读到实际效果的字段包装成可用控件。
- **面板约定**：第一批控件就采用清晰、高密度、小字号可读、单位明确的布局；定义数值精度、草稿／来源／生效标识和搜索定位，T02／T03 直接使用，不等待最终视觉统一。

## T01 执行结果：首版与自动验证通过，等待用户体验（2026-10-20）

**授权／目标**：用户明确继续 T01；只解决现有面板的参数身份、草稿和保存基础，不提前开发 T02 外形能力、T03 技能编辑或 T04 跨台导航。随后用户反馈测试窗口遮住当前操作，纳入同批启动器修正。

**方案核对**：保留两个独立草稿并分别补切换保存，改动小，但重复校验和来源逻辑仍会漂移；一次重建通用工作区与所有参数控件，入口可统一，但会超出本批并推迟可体验结果；采用共享纯数据会话＋现有面板适配，能复用既有 schema／命名方案并守住保存合同，因此推荐并实施第三种。该会话不持有游戏节点，后续可接进程边界，但不把同进程静态共享当作跨进程传输。
