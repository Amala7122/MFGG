# 批次对话模板

本任务按「一个批次一个对话」推进。批次清单、依赖与状态只在
[主文件](../实验与调试体系摸底.md) 维护；本目录分片只存细则、执行结果与用户反馈。

## 铁律

1. 一个对话只做一个批次；**30–60 次工具调用就收口**，不要挂着一个对话等用户验收。
2. 开工只读「开工读集」列出的文件，**不要通读** `docs/tasks/实验与调试体系/` 整个目录。
3. 前置批次处于「等待用户体验」时，只在其上做加法，**不改它的界面与契约**。
4. 分片里的计数与快照是当时的；开工用真实代码重新核对，不把快照当新基线。
5. 收口写回同一批次分片；不新建任务文档，不在主文件写逐轮日志。

## 一、开工（实施对话的第一条消息）

```
本对话只做 <批次号>（<批次名>）。

读这些就够：
- 主文件 docs/tasks/实验与调试体系摸底.md（只看批次表 + 本批状态行）
- 本批分片 docs/tasks/实验与调试体系/<本批文件>
- 依赖批次分片（按批次表依赖填，只读其「执行结果」段）
- 共用合同 docs/tasks/实验与调试体系/06-跨台返回与四台归属.md
- 改界面再加 docs/tasks/实验与调试体系/04-布局与全局调节入口.md

前置 <T0x/T0y> 现在是「等待用户体验」，本批只在它们之上做加法，不改其界面与契约。
开工第一步：用真实代码核对前置交付物是否仍存在（不读文档快照），再动手。
本批验收门槛：<从主文件批次表抄这一行>
范围外一律不做。发现必须先修的 bug，登记 docs/issues.md 后继续本批。
```

## 二、收口（本批结束）

```
收口，按主文件「每批统一交付格式」写。

1) 写回分片 <本批文件>.md，新增「<批次号> 执行结果」小节：
   新增可用流程 / 参数归属与保存范围 / 影响入口 /
   实际验证命令与证据路径 / 未验证项 / 下一批依赖
2) 主文件：只更新批次表本行「当前状态」与「步骤与状态」表相关行，
   不搬迁原文、不把分片内容写回主文件
3) 状态停在「等待用户体验」，不要写「已验收」
4) 本轮用户原话反馈逐条记入本分片
```

## 三、反馈修复（用户试玩之后）

```
本对话只处理 <批次号> 的用户反馈，不启动下一批。
反馈原文：<粘贴用户原话>

流程：先复现 → 在 docs/issues.md 按用户原话登记现象 → 修 →
自动验证 → 写回 <本批分片>.md 同一「执行结果」小节的反馈修复段。
不改其他批次范围，不顺手重构；失败产物保留，不覆盖上一轮证据。
```

## 四、细化批次（T04–T13 还是标题级时，先做这一步）

```
本对话只细化 <批次号>，不改任何代码。

产出：把 <本批文件>.md 补成与 T00–T03 同规格的内容——
范围 / 依赖与前置不变式 / 改动入口（真实文件路径）/
可判定的验收门槛 / 验证方式与证据形式 / 未验证项。
同步更新主文件批次表与分片索引。
细化完即停，等用户授权再开实施对话。
```

## 五、新分片的固定文件头

新建分片时照抄任一现有分片的开头四行：H1 标题、空行、两行 `>` 引用
（一行说明本文件是主文件的分片，一行说明状态以主文件批次表为准）。
以 [t04-第一条跨台实用闭环.md](t04-第一条跨台实用闭环.md) 的开头为准。

## 六、成本参照

- 每批固定读集约 **19–22k token**（主文件 7.8k + 共用合同 8.8k + 本批 1.5–5k）。
- 切片前整份文档一次读入约 **55k token**。
- 一个对话若超过 100k 上下文，后面的每一轮都在为前面重复付费；到点就收口。
