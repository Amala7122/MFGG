# AI 调试鼠标隔离

## 目标与反馈

- 用户反馈：「每次ai调试开运行模式的窗口都会抢我的鼠标，移动范围被锁定到godot的运行模式窗口范围」。对应 I-230（并行登记撞号后已校正）。
- 目标：自动验收与图形探针不锁定系统鼠标、不获取窗口焦点；手动编辑器试玩仍能捕获鼠标转视角。
- 范围：共用鼠标入口、项目内调用点、自动测试启动器及持续协作规则。不改战斗数值、镜头或用户显示存档。

## 已核对事实与判断

- 本机实际引擎为 `4.7.2.stable.official.ed1daf0bf`；无头 API 清单未暴露 mouse mode override。核对证据：`../../../_artifacts/godot-ruin_star_new/automation_mouse/20261019_210549_d2a289b4/logs/api.stdout.log`。
- 修复前，玩家、GameFlow 继续游戏、实验场快速开始、面板恢复及部分图形测试会直接设置 `Input.mouse_mode`；只隐藏控制台不能阻止捕获。现已统一改为 `MouseControl.mode`。
- 保留现状、仅按 Esc：下次启动/恢复仍会重捕获，淘汰。
- 仅使用无头：适合逻辑检查，但不能完成真实渲染截图；作为默认入口保留。
- 全项目永久禁用捕获/焦点：破坏手动试玩，淘汰。
- 推荐：自动运行显式标记 + 共用鼠标模式入口，逻辑请求与自动运行的物理鼠标分开；隔离工程从创建窗口前设置 no_focus。所有已有运行/探针通过统一启动器继承标记，包括子引擎。

## 改动入口

- [共用鼠标模式](../../scripts/mouse_control.gd)：所有自有脚本、测试与探针通过 `MouseControl.mode` 读写；自动标记下保留逻辑请求，物理鼠标始终 VISIBLE。未设标记时直接读写原生 Input。
- [统一启动器](../../tools/run_acceptance.py)：隔离工程创建前设置 no_focus/关闭置顶/窗口模式，给进程环境注入 `RUIN_STAR_AUTOMATION=1`，结果记录隔离标记；[探针](../../tools/run_probe.py)复用同一入口，子引擎自然继承环境。
- [回归](../../tests/test_mouse_control.gd)与[无头子进程夹具](../../tests/fixtures/mouse_mode_child.gd)：检查物理鼠标、请求语义、焦点标志、暂停、调用点绕过及子进程继承；已加入 core。
- [协作规则](../../AGENTS.md)与[工具说明](../../tools/README.md)：AI 后续禁止直接启动会捕获鼠标的原工程，自动运行默认无头，需要渲染才用受保护的图形入口。
- 一次性 API 核对脚本与日志保留在上述运行目录的 `tmp/api/`、`logs/`，作为本次诊断归档，不加入正式实现。
