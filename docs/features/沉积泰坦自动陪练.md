## 编辑器使用

启动后暂停，选择方案、种子、观察预算和自动／真人模式，再点开始。Tab 暂停／继续并显示面板，F5 按面板条件重跑。开始后的条件锁定，面板修改下次重跑生效。真人模式保留正式操作键，鼠标由运行窗口捕获。

配置：`data/testing/titan_sparring.json`。保存命名方案与设为默认分开；面板显示未保存状态。反应延迟单位秒、瞄准误差单位度、转速单位度／秒、距离单位米；预算到期只截断观察，不计死亡或通关，也不评价质量。参数范围以面板和配置校验为准。

诊断参数在同一滚动面板中，修改下次开始生效，可随命名方案保存；设默认仍须单独操作。`diagnostics.stall_seconds` 默认 4 秒（范围 0.5–30），`stationary_radius` 默认 0.25 米（0.01–2），`snapshot_interval` 默认 0.1 秒（0.016–1），`context_seconds` 默认 5 秒（1–15）。前两项是异常定位容差，不是难度或好玩分；第三项控制常态快照频率，第四项控制异常发生前保留多久。按 F5 用相同条件重跑，不必反复调到相同位置。

三种内置测试假设：持续绕射；读取可见预警后应对；迟反应、贪枪并使用狙击。它们不是新手／高手人口模型，也不能由机器胜率推导所有玩家的感受。控制器延迟读取可见目标和已发布地面预警几何，使用自己的真实冷却；不读取未公布选招和未来命中倒计时。记录器可记录内部状态用于事后归因，控制器不能使用。

## 批量运行与对照

在项目目录运行：

```powershell
python -B tools/run_probe.py tools/probes/titan_sparring.gd --task titan_sparring --timeout 600 --args --profiles=orbit,reactive,greedy --seeds=10420261014,10420261015 --seconds=180
```

默认**无头模式**，规则检查、故障注入、多种子批跑、旧记录分析与重放核对均不需要图形窗口。修改策略后可以传 `--reaction_seconds=0.35`、`--aim_error_degrees=2`、`--preferred_distance=12` 等六个数值字段。CLI 不保存参数；运行条件完整写进报告。需要检查界面、材质或预警实际显示时，加 `--graphics` 和 `--args` 后的 `--capture` 留下截图。无头模式不能验证人眼是否能看清提示；时限是进程安全门，不是战斗质量标准。

传 `--compare=<此前 reports/sparring/batch.json 的绝对路径>` 输出同条件配对差异。只配对审计未发现异常、且策略／种子／预算／模式／实际初始配装／初始位置与个体参数／陪练指纹／运行环境均相同的样本；玩法文件变化另列。异常、重放、缺少审计的旧报告与不同陪练版本会说明排除原因；无配对不能报已比较。报告记录 headless、DisplayServer、引擎版本和固定帧推进条件，不直接混比图形与无头结果。种子固定投放、策略和武器散布，但不承诺跨运行逐帧确定性，正式对照须重复多种子。

批跑默认保留所有原始结果，便于分析失败；用于自动门槛时追加 `--require-valid`，存在异常／未审计样本返回 2，运行错误返回 1。进程执行通过与战斗样本有效分开。

输入复现：

```powershell
python -B tools/run_probe.py tools/probes/titan_sparring.gd --task titan_sparring_replay --timeout 240 --args --replay=D:/.../inputs.jsonl
```

`inputs.jsonl` 旁须保留同次 `result.json` 和 `snapshots.jsonl`。读取源条件，在同一逻辑输入帧比较检查点的位置、血盾与 Boss 状态；默认容差为位置 0.5 米、Boss 生命 1、玩家血盾合计 0.1，状态须相同。首次超差立即停止并记录首帧／时间／误差；缺少检查点或只跑到部分检查点不能判重放通过。需要自动门槛时追加 `--require-replay-match`，未完成原局检查点核对返回 3。

录像是固定输入重放，用于定位问题；闭环策略重新决策用于比较参数，两者结论不能混用。共享随机流、墙钟相机震动与导航微秒预算等因素尚未隔离；即使同 seed 也可能偏离。当前保证核对并暴露偏离，不承诺完整确定性状态恢复。重放始终排除出正常战斗统计。

## 记录与判断

每次运行独立写入项目外 `_artifacts/godot-ruin_star_new/<任务>/<运行号>/`，面板可打开本轮目录。`reports/sparring/批次报告.md` 为批次入口；每局有 `result.json`、`结果.md`、`events.jsonl`、`inputs.jsonl`、`timeline.csv`、`战斗曲线.svg` 与 `snapshots.jsonl`。记录实际初始配装、代码指纹、起招及结果、预警感知、输入意图与实际生效、伤害来源、死亡前受击、资源与活动耗时。时间是过程坐标，不输出好玩分。

常态快照约 10Hz，包含 XYZ、速度、落地、碰撞法线／对象、Boss 当前实际处理分支、选招门槛与拒绝、导航规划阶段／结果、移动请求与放行速度、物理处理开关与顿帧恢复标记。只有挂接陪练记录器才采集；不额外做选招、寻路或战斗判定。控制器仍只使用可见信息，不能读取这些隐藏原因。

正常行动状态下，位置在容差内、没有新起招、没有攻击冷却等待且持续受伤超过阈值，自动标 `boss_pressure_lost`。蓄力、跃击与非行动奖励状态不据静止误报。运行中提示已留证，保存异常前后物理帧 `incident_001.json` 等（默认前 5 秒＋检测延迟、后 2 秒，每局最多 8 段；结束不足后文时明确截断）。它是结构化帧片段，画面仍须结合截图／重放检查。

原始 `outcome` 保留，另给 `analysis.sample_validity`、`eligible_for_balance` 和原因证据：异常为 `needs_review`，新记录未检出为 `no_detected_anomaly`，缺原因的旧记录为 `unverified_legacy`，不完整为 `incomplete_recording`，偏离重放为 `replay_diverged`。未检出不证明无 Bug。分支证据与最终根因分开，不能见导航等待便宣布坡度碰撞已确认；目前检测集中于受伤时的长期停摆，不是所有 AI／碰撞故障的完整诊断器。

先核对配装、操作录像和死因，再与人的反馈比较。能测实际失误代价和招式覆盖，不能自动证明提示清晰、动作舒服、挑战有趣或用户已满意。本入口满配直战不代表四波后玩家实际携带的配装；未来新增 Boss 机制时需补相应策略与事件，现有陪练不会自动学会尚未实现的三雷／三枪规则。

### 操作录像结果如何分析

「真人操作录制」保存输入和战斗日志，不是 MP4 或完整状态录像。AI 可以直接读取本地本轮目录，分析何时移动／翻滚／使用 E、Q、R、C，实际受击与招式、血盾恢复、正常／狂暴失误代价、换弹和输出中断。`inputs.jsonl`、`events.jsonl`、`timeline.csv` 和 `result.json` 应一起保留；只拿输入文件不能还原实际伤害与场景原因。

真人没有机器控制器的预警感知事件，不能据按键日志断言人何时看懂提示。新记录的 `input_result` 区分实际释放与被冷却／锁定等拒绝，`attack_released` 记录正式发射；不是仅拿按键当成功。读取时间线需用外层事件 time，不将 Boss brain 的内部活动时间误当整局时间。

已有真人／自动记录可以不启动战斗、直接无头分析（路径可指向目录或 `result.json`）：

```powershell
python -B tools/run_probe.py tools/probes/titan_sparring.gd --task sparring_analysis --timeout 120 --args --analyze=D:/.../reports/sparring/某局目录
```

独立输出 `reports/sparring_analysis/诊断报告.md`、`analysis.json` 和源文件指纹，原始实录不覆盖。旧记录仅有 X/Z，仍可发现停摆，但缺失的高度、碰撞和导航原因不会补造。重分析保留源重放审计，检查结束事件与状态尾部，避免把重放或截断记录变成正常样本。
