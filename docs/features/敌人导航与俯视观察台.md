# 敌人导航与俯视观察台

2026-10-12 精确追击优化：单环目标实验已按用户要求退役，原 [ring_chase_lab.tscn](../../prototypes/ring_chase_lab/ring_chase_lab.tscn) 路径保留为精确追击压力台，只有移动标记目标，无 P 键环模式切换。默认 256 体、WASD/Shift 移动目标、F 重置俯视；在标记 1.5 m 内且同层（脚下高度差 ≤0.35 m）近距回收、超过 60 m 掉队回收。旧 31.5 m 回收仅供探针显式 `--recycle-distance=31.5` 复现前后压力负载，不作为到达成功率。

共用 `NavSteering._contact_push()` 先判断上一帧不可行走表面接触及迎面推进，再做完整身体跨坎预验；实际 `Ground.move()` 受阻后的跨坎检查、步高与身体扫掠保持原样。`NavProjectionCache.owner_valid()` 按地图 RID 和同步 iteration 缓存原生最近面 owner 的有效性，不再按每个位置格重查；几何增删及区域状态变化同步后重新获取。它只判断是否存在可投影几何，**不判断该位置在面内或路径可达**；4.7.2 的最近面查询包括禁用区域，路径搜索才排除禁用区域，见 [4.7.2 原生查询实现](https://github.com/godotengine/godot/blob/4.7.2-stable/modules/navigation_3d/3d/nav_mesh_queries_3d.cpp)。

旧精确压力负载下，256 体、三种持续移动轨迹种子、每轮 900 帧/预热 120 帧，各轮 p50 算术平均 29.617→24.519 ms（−17.21%）、p95 平均 38.496→30.567 ms（−20.60%）。完整正式空间策略链路的单轮全区域对照 p50 40.108→40.035 ms，基本未变，不能推广为正式场景同等提速。独立跨坎、旋转障碍及移动目标专项通过；全区域严格到达仍存在 I-091，优化前代码也复现同一批失败，未解决已有通行问题。证据与当前状态见 [同一任务记录](../tasks/单环追击模型.md)。最近点缓存的边界误差 I-089 本轮未修；未宣称正式 256 敌人容量或用户观感已验收。

当前状态（2026-10-11 实施轮）：用户要求实施 APS 移植方案，P0–P4 与 P6 已落地 —— 形状数学（圆角打分、弧长重采样、弧形/蛇形包络、车道偏移）、两级验证与分级回退链、保留路线的时效语义、观察台参数与三段路线。持续移动目标的四相位对照显示走停指标明显改善（零速比例 0.393/0.414 → 0.105/0.088，最长连续零速 497/498 → 151/221 帧）。**I-064 的单次阻塞分帧（P5）与正式接入评估（P7）未做**；观感与性能是否满意仍由用户判定，未通过验收。实施细节与证据见 [APS 路径算法移植实现文档](APS路径算法移植实现文档.md) 第 15 节与[任务记录](../tasks/UE_APS敌人导航插件研究.md)。

## 编辑器入口

打开 [navigation_lab.tscn](../../prototypes/navigation_lab/navigation_lab.tscn)，按 **F6**。默认加载正式主场景的地形、建筑、石块与树干碰撞，初始使用俯视相机（右键可旋转，F恢复），投放 **64 个全区域测量体**。只生成导航测量体和移动目标，没有玩家、攻击、受击、死亡、技能或刷怪流程。

- **WASD 连续控制目标**（面板可关）：W/A/S/D 移动，Shift 冲刺 ×1.7，「目标速度」默认 3.2 m/s。目标每物理帧按真实地面推进，前方没有可站立地面时不动，不会瞬移过沟。用来观察敌人在目标持续移动时是否**连续改线**；关掉开关后仍可用左键点击设置目标。
- **启动后不自动寻路**：F6 进来先停住，确认参数后点顶部「▶ 开始」或按**空格**才开跑；状态栏显示「未开始 / 运行中 / 已暂停」。左键设置目标；Shift＋左键增加测量体（最多 256 个）；滚轮缩放。
- 环模式下的圈号标注：场景里**只画一个很小的数字**（①②③④… 2D 叠层，屏幕固定 12px，不随缩放变化、不挡画面），每个数字放在对应环的圆周上；半径 / 拖动阈值 / 已拖动次数放在左侧状态栏的「环目标」图例里，不占画面。左侧每个测量体一行是「已进① / 奔向② + 状态 + 停留 + 距目标米数」，报告问题时可以直接说几号体和几号环。
- 观察台操作：**左键**设目标、**Shift＋左键**加测量体、**右键拖动**旋转、**中键拖动**平移地图、**滚轮**缩放；**R = 重新投放**（目标回初始点 + 测量体按种子重投 + 环状态与统计清零），**F = 重置视角**。面板最上方也各有一个按钮，并常驻一行操作提示。所有选项都有悬停说明（tooltip），包括单位、范围和生效方式。
- 「64 / 128 / 256 个」快速启用全区域分层投放并重播；全区域开关可与同一固定种子组合复现。
- 种子、数量改变后按「相同种子重播」，得到可重复起点。速度即时生效；暂停保留当前轨迹。
- 三段路线分开观察：**蓝色**基础网格路径（成形前）、**绿色**成形路径（APS 流水线输出）、**彩色**实际轨迹。左侧显示到达数、停滞数、每个测量体状态与停留时间，以及成形统计（候选数、一级/二级查询数、缩幅命中档位、整条终检失败次数）。
  - 画线口径：**空间决策开启时只画空间路线**（绿=成形路线、蓝=基础网格路径、彩色=实际轨迹），不再画 NavSteering 的 Agent 路径 —— 它永远指向玩家，会让人误以为「没进环的追击者也在连玩家」。只有关闭「空间通行决策」时才画 Agent 路径。另外每个追击者会画一个**橙色竖标**表示当前规划用的目标点，直接看得到它落在哪条环带里。
- 「同心环带目标」**默认关闭**：开启后敌人奔向按「铁圈」模型维护的环圆心（不是玩家当前位置）。**目标在一圈里自由移动时该圈不动**；只有走到圈的边缘继续往外，才把这一圈拖着走。拖动阈值 = 环间距 `T_k = R_k - R_(k-1)`，第 1 环的阈值就是 `R_1`。
  - 面板入口：**同心环数量**（2~8）、**逐环半径输入框**（每一圈自己填，不再强制 2 倍递增）、**按 2 倍递增填充**按钮、**拖动方式**下拉框（**弹开** = 越过边缘跳到内圈位置，默认；**平滑** = 圆心沿边缘滑行）。
  - **第 1 环是基础过滤器**：追击者进到第 1 环里（离 `A_1` ≤ 0.9·`R_1`）就转精确追击，之前逐级向内。「多早转精确」的上界是 `2·R_1`，默认环半径 6 / 16 / 40 / 90 米。
  - **环层级容差 m**（默认 10）：追击者脚下与目标支撑面的落差超过它就回落精确目标。主场景坡地/台地高差常常超过 2.5 米，容差过小会把远处敌人全部挡回精确目标（实测容差 2.5 米时远处计划请求一半以上被挡回），这一项直接决定圈组能不能生效。
  - **投放于第 N 环外**（0 = 不限）：只把测量体投放在第 N 环之外，用来观察远处敌人到底寻路到圈内还是到玩家；报告记录「环外剔除」数量。
  - 场景里画每一环的圆和**很小的圈号**（①②③④，12px 2D 叠层）；半径 / 拖动阈值 / 已拖动次数在左侧状态栏「环目标」图例里，每个测量体一行显示「已进① / 奔向② + 状态 + 停留 + 距目标」。
- 「空间通行决策」开启时使用正式空间控制器；关闭时观察同一个 NavSteering 的原生网格跟随，地面安全检查仍保留。
- 「仅在连通区域投放」默认开启，遵守正式投放的连通要求。关闭可保留导航孤岛起点，观察真实不可达结果。报告记录请求位置、实际位置、是否连通、是否重新采样，不把不可达测量体计为到达。
- 「保存本轮测量报告」写入项目外 `_artifacts/godot-ruin_star_new/navigation/<运行编号>/reports/`，包含配置、种子、目标、投放记录、位置、累计路程、最长停滞、重规划次数与局部脱困次数。

观察台脚本为 [navigation_lab.gd](../../scripts/prototypes/navigation_lab.gd)，测量体为 [navigation_test_actor.gd](../../scripts/prototypes/navigation_test_actor.gd)。它们没有复制另一套寻路算法。
6. [nav_ring_anchors.gd](../../scripts/nav_ring_anchors.gd)（新增，**默认关闭的候选路径**）：同心环锚点。第 1 环以内仍是精确目标；第 k 环圆心只在目标离开超过 `T_k = R_k − R_(k−1)` 时被拖到目标当前位置，越外圈越钝；敌人越过第 k 环外边界就奔向该环圆心，逐级向内。锚点取自目标真实站过的位置，因此天然落在导航面、天然连通，不需要向圆周取几何点。环状态按目标共享，每物理帧只同步一次、零路径查询。开关 `CombatSpatialController.ring_goal_enabled`，对照见 [test_navigation_ring_goal.gd](../../tests/test_navigation_ring_goal.gd)。**2026-10-11 二次实测仍未通过门禁，且原因已定位**：先前的对照是在「环带覆盖参数从未生效」（I-082：控制器在 `job.begin()` 之后才设置 `goal_override`，而规划器只在 `begin()` 内读取）的前提下做的，不能代表环带模型本身。修好覆盖顺序后环带目标真正生效，环带组两项测试失败：接战链「真正在追的个体」24 → 13/14，最长连续零速 218/86 → 718~865 帧，`replans` 由 838 掉到 11~39，零速帧大部分属于 `relocate/checking_retreat` —— 到达环带目标后不再触发重画（I-084）。因此**保持默认关闭**，等「到达环带目标如何算消化并进入下一档」理清后再评估；同一轮还修好了 `_publish_route` 里让粗略目标结果永远作废的过期判据（I-074）。

## 共用参数与保存

项目默认在 [data/navigation/steering.json](../../data/navigation/steering.json)，共 11 个键；运行面板中的参数即时影响共用导航，改变后显示「未保存」，需要显式保存才能成为下次启动的默认值。默认值全部保持移植前行为（`arc_strength = 0`、`lane_offset = 0`，只有 `corner_rounding` 生效）。

| 参数 | 单位 / 范围 | 默认 | 作用 |
|---|---|---|---|
| 转角圆弧 corner_rounding | 米，0～2 | 0.8 | APS 圆角的切除距离来源；空间不足或候选被拒时保留原角点 |
| 路线侧偏 lane_offset | 米，−3～3 | 0 | 转角处按转角强度加权的车道偏移；候选按 8 档相对缩幅回退 |
| 目标移动重算 goal_replan_distance | 米，0.2～3 | 0.8 | 目标累计移动超过阈值才重建路径；按请求时采样点比较 |
| 弧形强度 arc_strength | −3～3 | 0 | APS `ArcStrength`：正=一侧、负=另一侧；`|S| < 0.1` 视为关闭 |
| 弧形中点 arc_num_midpoints | 整数 1～6 | 3 | Smooth 的包络指数 / Wavy 的波峰数；同时是圆角细节采样上限 |
| 弧形模式 arc_mode | smooth / wavy | smooth | 单侧鼓包 / 蛇形交替（`ComputeLocalSideSign`） |
| 弧形最短 arc_min_distance | 米，0～50 | 3.0 | 低于此水平距离不做弧形（APS 300 uu） |
| 重采样段长 arc_resample_length | 米，0.5～10 | 4.0 | 弧长等分目标段长（APS 400 uu） |
| 成形点数上限 shape_max_points | 整数 16～192 | 128 | 重采样输出点数上限（APS 硬上限 128） |
| 密集点隔点形变 arc_sparse_warp | 开 / 关 | 开 | 点数 > 64 且强度 < 1.5 时隔点形变 |
| 整条终检 shape_final_gate | 开 / 关 | 开 | 整条路径逐段复检；失败则连圆角一起丢弃，回到基准路径 |

「另存命名方案」只保存到 `data/navigation/presets/<名称>.json`；读取命名方案只改变本轮预览。**「将导航参数设为项目默认」才改默认配置**。种子、数量、速度是观察条件，不写入正式敌人数值。

高低差路径和大型身体优先保留已验证的落脚线与能力入口；平滑不能替代步高、坡度、支撑、净空和返程检查。导航烘焙配置仍在 [game_config.json](../../data/game_config.json) 的 `navigation` 段，跨坎高度受真实 [ground_movement.gd](../../scripts/ground_movement.gd) 上限约束。

## 实现与通用边界

正式近战、远程和使用 NavSteering 的原型共享以下实现：

1. [nav_steering.gd](../../scripts/nav_steering.gd)：稳定跟随、目标变化后刷新、接触偏转及脱困。绕行点必须验证入口和后续路线。
2. [spatial_route_planner.gd](../../scripts/spatial_route_planner.gd)：导航点落到真实地面，逐段验证完整身体；高度判断依据真实落脚面，补偿体素误差。通道中点或最短通道落脚线失败时试另一种；无支撑中间提示点只能在后续实际连接仍通过全身检查时略过，目标不能略过。
3. [nav_arc_shape.gd](../../scripts/nav_arc_shape.gd)（新增）与 [navigation_path.gd](../../scripts/navigation_path.gd)：APS 的「基础路径 → 自适应圆角 → 弧长重采样 → 弧形/波形/车道偏移 → 逐点验证 → 缩幅/绝对宽度/保留基准点回退 → 整条终检」按源码行号移植；`navigation_path` 只做参数入口与调用。基础寻路仍是 Godot `NavigationServer3D`，段验证一律用本项目的完整身体通道（一级投影门禁先筛），不放宽到 APS 的纯 navmesh LOS。
4. [combat_spatial_controller.gd](../../scripts/combat_spatial_controller.gd)：实际净位移不足时试验两侧和后方的安全中间点；失败则从实际位置重算，避免立即进入永久入口等待。**目标持续移动时的动态改线**：在规划器已证明为「直行」的段上（`walk_route` 里整段 `ground_segment` 通过的那种），最后一段的瞄准点从「规划时刻的落点」连续切换为「当前目标」，每 0.08 秒重估一次本地身体探测（`NavSteering.live_direct_ok`：0.3 米身体扫掠 + 落脚检查），并带 75° 改瞄容差角；绕行/跨越段仍严格按路点走，规划器始终是拓扑与通行的权威。开关 `CombatSpatialController.live_aim_enabled`，独立对照见 [test_navigation_live_aim.gd](../../tests/test_navigation_live_aim.gd)。只有规划器验证过完整身体直行通道，才允许直行风格清除绕行路线，不能仅凭细射线视线。保留路线有明确时效语义：请求时采样的结果不因目标继续移动而作废，目标位移触发的重算受 `replan_interval` 限速，避免多体排队时互相拖住（对照与实测见移植文档 15.4）。
5. [spatial_query.gd](../../scripts/spatial_query.gd)、[navigation_region.gd](../../scripts/navigation_region.gd)：实际身体/支撑检查与物理步高一致的网格；接触余量内允许经扫掠证明安全的向外离开，向内撞墙和真实实体穿入仍拒绝。

这些规则不读取地图名、障碍名称或测试坐标。观察台使用主场景，独立回归重新构造并旋转墙、墙角、圆柱树干和球形岩块；正式地图几何没有为本任务修改。真正断开的区域保留不可达结果，不穿墙、不传送、不把深坑当成缓降。

这次借鉴的是 APS 路径后处理和失败回退机制，不是直接运行 UE 插件。作者演示视频的观感、UE 插件性能以及所有未来地图的行为没有据此验收。

## 复现和自动检查

```powershell
python -B tools/run_probe.py tools/probes/navigation_main_scene.gd --graphics --task nav_capture --timeout 240 --args --frames=900 --ring=1
python -B tools/run_acceptance.py --tests test_navigation_main_scene test_navigation_obstacles test_combat_spatial_policy test_combat_spatial_navigation test_combat_spatial_capabilities test_combat_spatial_attacks test_enemy_deployment test_sanctum_layout --task navigation --timeout 240
python -B tools/run_acceptance.py --tests test_navigation_stress test_navigation_stress_soak --task navigation_stress --timeout 1200
python -B tools/run_probe.py tools/probes/navigation_main_scene.gd --graphics --task navigation_preview --args --count=128 --frames=900
```

[test_navigation_main_scene.gd](../../tests/test_navigation_main_scene.gd) 使用三个种子、真实主场景碰撞与共享控制器，并检查 0.2 米缓降允许、0.65 米断落拒绝。[test_navigation_obstacles.gd](../../tests/test_navigation_obstacles.gd) 检查 16 组独立障碍、不同身体宽度下的移动目标、受阻旧路点脱困，以及断开的两块地面。

[test_navigation_stress.gd](../../tests/test_navigation_stress.gd) 查询完整 8×8 区域，初始站位只筛实际支撑/净空，不预筛掉规划失败路线。六轮累计 960 个体测量，包括 64 个体汇聚、128/256 个体跨区域、128 个体最大侧偏、128 个体中途迁移目标，以及观察台自身的 256 个体全区域投放。高密度同分区使用固定种子的不同落脚点，报告记录实际不同起点数量；孤岛/断路保留独立不可达统计。

基础六轮每轮最多 90 秒物理时间。[test_navigation_stress_soak.gd](../../tests/test_navigation_stress_soak.gd) 追加 256 个体、固定种子 57721，每 15 秒换目标，连续四次跨区域迁移，最后保留 90 秒追踪窗口（总上限 150 秒）。七轮累计 1216 个体记录。报告记录每个体最长停滞、最后位置/目标、路线刷新/脱困及步进耗时分位数。无界面压力测量只测试移动/物理/导航，耗时不是包含完整战斗与渲染的帧率承诺。

实际运行证据和用户反馈持续写在 [同一任务记录](../tasks/UE_APS敌人导航插件研究.md)。自动通过只表示这些可重复用例通过，移动观感等待用户试玩。

本轮七轮压力已通过，[实测汇总](../../../_artifacts/godot-ruin_star_new/navigation_pressure_final/20261011_111617_62d70296/reports/navigation_pressure_summary.md) 保留不同起点数和所有不连通项。256 个体全区域轮无渲染帧间 P95 为 42.768 ms，持续迁移轮为 53.679 ms；高密度性能仍有瓶颈（I-064），不能按功能通过宣称达到 60 FPS。
