# 通用实战陪练

本页是已落地工具的唯一日常用法。要决定后续改什么、先做哪批，看[本对话执行入口](沉积泰坦Boss战斗节奏实施方案.md)；下面的方法研究是设计依据，不另构成待执行计划。工具首版已完成，经验模型和完整重放的限制不自动升级为后续玩法前置。

## 无头重复测试

### A7新循环策略与窗口对照（2026-10-17）

命名方案新增 `body_control`（看预警、只绕射身体）、`break_priority`（破解优先）、`break_delayed`（迟反应／偏瞄的破解）。原orbit／reactive／greedy保留，默认仍为reactive。破解只读取已显现模型位置、红晶体、可见护罩和自身资源；不读取进度、5秒剩余或未来选招。短期几何错误会真实影响策略，不能给机器人透视命中或免伤来补偿。

结果增加 `cycles`：实际盾／晶体进度增量、零散布狙击逐发轨迹（身体／晶体／保护／世界／未中）、保护拦截、有效窗口实际扣血／当时发射次数、是否被死亡／预算截断。`cycle_clip_*.json` 是关键窗口和无效狙击前后的诊断快照，不是视频；逐发轨迹仅在正式射击前旁观同一条射线，不能代替实际破击计数。

`batch.json.cycle_contrasts` 声明唯一允许不同的轴：策略开关或倒地时长。初始配装／位置、反应误差、种子、环境和工具指纹仍须相同；缺证据、异常、重放均排除。迟反应／偏瞄不能假装成只改破解开关的严格配对；未进入倒地有效窗，明确拒绝比较窗长收益。失败、截断与排除原因保留，不反复筛掉不想要的结果。

`--analyze=<原录制目录>` 支持旧真人快照的实际进度观察下界和攻势组序列；没有逐发判区就明确缺失，不追认每枪原因。新局另存攻势种类、单次重招即收组比例与实际序列。固定种子不承诺逐位确定性，仍需配对多个条件和适量重复；时长不作为好玩分，脚本结果不代表人群。

先在面板保存编组与策略，再使用「复制无头批测命令」。可选当前／全部已保存策略以及每种子重复次数；命令使用面板中的场景、编组、配装、等级、倍率、预算和种子，运行不覆盖当前局。

项目目录中也可直接运行：

```powershell
python -B tools/run_probe.py tools/probes/combat_sparring.gd --task combat_sparring --timeout 900 --args --groups=melee_patrol,mixed_patrol --profiles=orbit,reactive --seeds=10420261014,10420261015 --repeats=2 --seconds=60 --require-valid
```

这是 2 组 × 2 策略 × 2 种子 × 2 重复；种子列表与重复分开，重复不冒充新增独立种子。CLI 支持 `--scenarios=titan_sanctum,sanctum_mixed`，`--enemy_level=15`、`--count_multiplier=2`、`--loadout=initial|mid|max`；策略原有六个数值覆盖继续可用，条件写入每局。

**默认无头、真实时间推进。** 正式远程有 `Time.get_ticks_msec()` 限流，固定帧加速会扭曲出手频率。因此两陪练 CLI 默认不用 `--fixed-fps`，以 `--max-fps 60` 运行，记录活动墙钟与物理帧节奏。暂停扣除；无法核对节奏就排除实战对照。无头减少渲染，不承诺把一分钟实战压缩成几秒。

显式加 `--pacing=fast` 可做加速机制快测，报告标 `mechanics_only`、不进入实战难度统计。`run_acceptance` 的定向规则／故障注入仍用加速无头；这类通过只证明规则和记录能力。只有 UI、材质和预警实际可读性才加 `--graphics`；必要截图再加 `--args` 后的 `--capture`。

`--require-valid` 遇到异常、缺能力、时钟未核对、快测或重放样本返回 2；运行错误返回 1。执行正常结束不等于战斗样本有效。批次大时调整进程 `--timeout`，观察预算只截断，不作好玩或难度分。

## 报告如何读

每局的 `result.json`、`结果.md`、`inputs.jsonl`、`events.jsonl`、`timeline.csv`、`snapshots.jsonl` 与 SVG 保存在项目外独立运行号中。批次从 `reports/sparring/批次报告.md` 进入。

先看样本有效性与时间审计，再看编组汇总：全部／有效数、玩家死亡、击败敌人、观察截断、覆盖策略／种子与一秒峰值血盾损失。异常样本不混入死亡率；截断不算获胜。全败只称「这些已完成有效样本全败」，不能由有限策略穷举出所有操作下数学必死；出现获胜样本也不代表所有玩家都能应对。

逐局看实际初始配装、真实投放对象、局内 ID、逐对象状态／剩余生命、完整伤害与来源、命中前翻滚／冷却／无敌帧、资源中断及最后受击。`pressure` 给一秒观察窗内的实际血盾损失峰值、涉及对象和最短受击间隔；它是承压事实，不是不可避免证明。来源不明保留 unknown，不补造身份。

普通快照约 10Hz。正常行动停摆且持续受伤、长时间持有非预期物理暂停，以及未观察到死亡便消失，逐对象留证并影响有效性。正常蓄力／防守／硬直与声明为预期的暂停有独立语义；不把一个对象仍活动当作全场正常。未知敌人状态、原因或预警能力明确缺失，不能套泰坦编号得到通过。

`needs_review` 是复核线索，不自动证明敌人有 Bug；合法地形优势也须结合预期判断。原始胜负和受影响对象／伤害仍保留，不能把排除当作删除不合预期的结果。策略使用几何视域和射线可见性，不识别像素或雾中的人眼辨识度。

异常片段 `incident_*.json` 保存事件前后物理帧；真实死亡另存 `terminal_player_dead.json`，保留最后的交战状态并标结尾截断。这些是结构化证据，不是 MP4。`capture_cost_usec` 仅为快照写入函数计时，不包含全部适配／策略或整机开销。

旧 CSV 的 `boss_hp`、`initial_boss`／`final_boss` 等字段保留兼容：在组战中表示敌方总生命；空间／状态列只是当帧一个对象的兼容投影。多敌分析以 `opponents` 和 `snapshots.jsonl` 为准，不能拿兼容列推断整场所有敌人。

## 离线核对、重放和比较

```powershell
python -B tools/run_probe.py tools/probes/combat_sparring.gd --task sparring_analysis --args --analyze=D:/.../某局目录
python -B tools/run_probe.py tools/probes/combat_sparring.gd --task sparring_batch_review --args --analyze-batch=D:/.../reports/sparring/batch.json
python -B tools/run_probe.py tools/probes/combat_sparring.gd --task sparring_replay --timeout 240 --args --replay=D:/.../inputs.jsonl --require-replay-match
```

源文件保留；新运行输出复核结论与源批次指纹。旧缺墙钟记录为 `unverified_timing`，缺原因不补造；缺结束／尾部标记录不完整。重分析保留原重放偏离与时间审计，不把它洗成正常局。

重放读取同目录条件与状态检查点，按同一局内输入帧比较玩家和**所有对象**的身份、位置、生命、状态与存活。首次超差停止并记录具体对象；只核对部分检查点不能报成功。`--require-replay-match` 未完成核对返回 3，重放始终不参与正常交战胜率。共享随机流、导航微秒预算等尚未全部隔离，当前提供偏离核对，不保证完整确定性还原。

`--compare=<此前 batch.json>` 只配相同编组／条件、实际配装／初始世界、工具指纹与运行环境的有效样本；玩法指纹变化另列。不同编组用组级结果呈现，不伪装成同条件配对。无可配样本明确失败。人眼提示、动作舒服与否和挑战趣味仍需少量候选体验，不由机器结果代判。

## 真人操作、行为分析与经验模拟

在 F6 面板选「真人操作录制」，填玩家代号与可选自报风格。标签只是采集备注，系统不因写了「高手／激进」就假定行为如此。开始后使用正式键鼠、血盾与武器；Tab 暂停，结束会自动保存，面板自动指向本局目录。不同玩家可填不同代号，同一玩家保持代号以便分层；anonymous 代表身份未知，不据此数独立玩家。录制是游戏内的输入与遥测，不从 MP4 猜精确按键。

原有输入之外，新版每物理帧保存版本、实际步长、鼠标捕获状态、移动与瞄准意图、实际位置及公开情境。公开情境约 10Hz，来自相机视域／射线与已发布预警；不声称知道人眼是否看见、是否听到声音、脑内察觉时间或未来选招。未适配普通近战没有地面预警时，不能把「未观测到预警响应」写成反应差。

真人键鼠采集需要图形窗口：本轮无头注入无法完成真实鼠标捕获，因此只用于输入结构与动作通路；已另用图形模式核对捕获／释放、步枪与狙击实际出手。已有图形录制的分析、汇总、固定输入核对和经验模拟可无头跑，使用记录中的捕获状态，不要求无头环境再捕获鼠标。

记录目录新增 `human_analysis.json`、`真人行为分析.md`、`movement_path.svg`；满足新版合同且足够长时生成 `human_model.json`。分析覆盖：

- **移动和走位**：移动输入与实际水平路程分开；速度／可见目标距离／期望视角转速的 p10／p50／p90，横移、后退、朝目标靠近／远离／切向移动、输入反转、移动键有输入但位移低、轨迹和 2m 占用格。目标是当时最近的可见对象，不把它当玩家实际意图。输入卡住、被击退和走位策略须结合事件复核。
- **攻击和资源**：开火／瞄准／移动开火占比，危险区内仍按住开火的占比，瞬时动作请求、已观察到生效／失败与原因、正式武器实际出手。按住开火不等于有子弹或实际造成伤害。
- **响应**：首次几何可见且覆盖玩家的公开预警到闪避请求、移动输入明显变化的间隔，逐次保留已移动／已翻滚、冷却、锁定、同步或可能提前操作、未响应和记录结束。只有满足条件的请求给分布，同时给全部曝光与未响应；不将未响应记 0 或丢弃后声称反应快。采样约有 0.1s 不确定性，它是可观测响应间隔，不是纯生理反应时间。只有动作／声效提示而无公开预警的招式仍是缺测。

面板可选择既有录制目录，再用「分析／生成经验模型」「原操作重放」「此风格模拟当前编组」。离线分析写本次运行的新目录，不覆盖源局。原操作重放恢复源条件，检查帧序／完整性／步长／捕获状态、引擎／物理频率、玩法指纹和各对象检查点。旧输入仍可读取，但缺失合同或版本不同不能取得成功复现资格；首次偏离后不把画面当原局证据。确定性回滚尚未实现。

经验模型是**带公开情境的真人操作片段检索基线**，不是已训练完成的人类替身。按可见目标、距离、人数、血盾、弹药／装填、危险曝光时长、公开进度、翻滚和锁定状态检索约 0.2s 操作片段，保留联合按键、移动与相对瞄准误差；公开目标可重新对齐。没有覆盖就中性输入并报告，不偷偷回退到高水平脚本。

模型末四分之一连续时间段留作粗略首帧诊断，训练与留出之间留 1s，避免随机拆相邻帧的泄漏；这不是独立玩家或独立场次验证。模型运行另给覆盖率、来源／文件指纹及 `style_comparison` 的走位、转向、距离、攻击差异。不同敌人会改变指标；当前所有经验模拟均标未独立验证、排除正常难度统计。完整导航、长期策略与人的认知没有被学习。记录达到 120 帧只是生成基线的程序门槛，不是足够训练的行业标准。

```powershell
# 原局行为分析，产物含经验模型（符合合同才生成）
python -B tools/run_probe.py tools/probes/combat_sparring.gd --task human_review --args --human-analyze=D:/.../某局目录
# 原操作重放，默认真实时间无头；偏离返回 3
python -B tools/run_probe.py tools/probes/combat_sparring.gd --task human_replay --timeout 240 --args --replay=D:/.../某局目录/inputs.jsonl --require-replay-match
# 经验模型在选定组中重复运行；它仍是假设样本，不能要求 --require-valid 通过
python -B tools/run_probe.py tools/probes/combat_sparring.gd --task human_model --timeout 600 --args --model=D:/.../human_model.json --groups=melee_patrol,mixed_patrol --seeds=10420261014,10420261015 --seconds=60
# 多玩家资料清单汇总
python -B tools/run_probe.py tools/probes/combat_sparring.gd --task human_dataset --args --dataset=D:/.../dataset_manifest.json
```

资料清单用 JSON：`{"recordings":["D:/.../玩家A第1局目录","D:/.../玩家B第1局目录"]}`。可放在外部运行 `reports/` 中。汇总按实际玩家标签、遭遇／配装／编组与玩法版本分层，保留逐局分布；同输入源重复、原局回放、模拟、自动注入、缺合同与异常均不增加有效真人样本数。不用总帧数当独立玩家数，不把多次回放算多次观察。原始异常记录仍出现在资料清单中。

### 方法依据与独立判断（2026-10-16）

公开成熟做法分为玩家遥测画像、按情境／序列建模、模仿学习与验证；不存在一个通用「移动＋命中＋反应」分数能直接评价体验。

- [Player Modeling，Yannakakis 等](https://drops.dagstuhl.de/entities/document/10.4230/DFU.Vol6.12191.45)给出玩家建模的分类框架；行为事实、体验推断与预测用途需要区分。本项目优先可解释行为事实，不从胜负推情绪或人格。
- [Drachen 等的商业游戏遥测比较](https://arxiv.org/abs/1407.3950)及[射击／角色游戏案例](https://andersdrachen.com/wp-content/uploads/2014/07/gunsswordsanddataclustering-of-player-behavior-in-computer-games-in-the-wild_cig2012.pdf)展示聚类／原型画像，也指出解释性问题。当前没有足够独立玩家数据，故不强行套「激进／保守／高手」簇；先留连续指标、情境与完整序列，后续有数据再检查自然分组。
- [Unity ML-Agents 官方文档](https://unity-technologies.github.io/ml-agents/ML-Agents-Overview/)区分 BC、GAIL 和 RL，示范包含观察与动作，BC 受示范状态覆盖限制。[DAgger 原论文](https://arxiv.org/abs/1011.0686)讨论序列决策中由策略引起的数据分布变化。推论：只复制原按键或拟合几个平均数，不足以换场景代表原玩家；当前片段模型只作透明基线，保留覆盖缺口。没有安装 Unity／引入训练服务，也没有把近邻检索冒称神经 BC／GAIL。
- [Riot 的用户研究说明](https://www.riotgames.com/en/work-with-us/disciplines/insights/get-data-informed-on-the-insights-blog)将遥测与实验室观察结合。本项目同样保留少量实际体验；遥测能指出发生什么，不能直接说明为什么不舒服。

本轮推荐：先把真人资料采准、把行动和情境说清，再用独立完整场次检查经验模拟的行为分布、失败方式和覆盖。暂不选高成本 RL／GAIL 训练：当前样本和独立验证集不足，增加模型复杂度不能补足证据。0.2s 片段、1s 留出间隔、8m 检索距离容差等均为可在 `sparring_human_data.gd` 调整的工程基线，不是论文保证的阈值。
