# 测试台参数草稿与保存

当前视觉／战斗原型专业页面共用完整草稿与参数定义，按唯一归属开放编辑，通过“外形 ↗／技能 ↗”往返；战斗空间台继承参数入口。三种纯外形保持即时编辑，裂甲兜虫战斗实体新增同草稿重建。T03首批为三线重击接入定格几何／时序编辑与同草稿试打；正式场景暂停拾取及实战／编组往返仍待T04–T06，其余模型编辑后补T13。

七种敌人的面板沿用八类公共语义，并增加“观察本草稿”：单体、固定目标、指定技能重播、范围与实际部位／弹体轨迹、暂停／单帧／慢放。三线重击可选“定格编辑”，参数输入复用本页同一控制器，错误／原文／草稿也共用。见[统一参数与攻击观察](敌人统一参数与攻击观察.md)及[全部732字段映射](敌人统一参数表.md)。这里的草稿／保存边界继续适用；完整肢体时间轴未接入。

## 从哪里打开

- Godot 编辑器打开 [战斗原型场景](../../prototypes/combat_lab/combat_lab.tscn)，F6 运行，在程序化敌人行点击“调参”。当前支持六种小怪及沉积泰坦。
- 打开 [视觉场景](../../prototypes/visual_lab/enemy_visual_lab.tscn)，F6 运行，选择爆囊爬兽、棱眼蛛或裂甲兜虫的**纯外形条目**，右侧编辑外形；裂甲兜虫的**战斗实体条目**也可编辑，修改后重建模型／碰撞／导航。其他战斗宿主的外形编辑尚未接入，显示只读与能力说明。
- 战斗空间测试台继承已有战斗面板；当前没有新的统一首页或从正式场景暂停点击跳转的入口。
- 敌人配置区采用两行顶部工具栏：标题／已选数量／统计／“?”一行，等级／无敌／敌不死／个体差异／循环一行。说明悬停“?”或相应控件查看；保存提示为空时不占位，非空时显示一行摘要并可悬停看全文。
- 底部“开战／实战陪练／继续／清场／全不选”排在一行，只有暂停战斗时显示“继续”。短按钮保持原动作与保存范围，完整用途在悬停提示中。
- 大部分垂直空间留给敌人列表；七种程序化敌人每行都有“调参”，长名称不挤掉按钮，可滚动到最后一行。战斗空间台左侧也采用三行紧凑的预设／起点工具区。

## 调整与保存

| 操作 | 实际作用 |
|---|---|
| 切对象／方案 | 同一运行进程保留各对象／方案的草稿、修订和候选名称；切回来继续编辑 |
| 搜索 | 按参数名称、字段名与模块定位；战斗面板会跳到首个匹配分页 |
| 撤销／重做 | 共用64步历史，每步记录模块；只处理最新的本模块操作。最新操作属于其他模块时提示通过入口处理，不跨过中间历史 |
| 还原外形／还原战斗 | 仅恢复本模块最近载入／保存时的值；战斗“载入基础值”也仅作用于战斗模块 |
| 撤回输入 | 仅撤回未提交文字，保留已经进入共享草稿的修改；不写磁盘 |
| 左上角“← 返回”／Alt+Left | 按调用栈逐级返回；保留草稿、错误原文、对象、搜索、分页和相机。独立F6无调用方时禁用并说明；进入参数页可返回配置 |
| 保存候选 | 保存同对象外形＋战斗整份已提交草稿。任一专业模块仍有未提交输入时提示先处理；不切换默认，不改正式Boss指定 |
| 覆盖同名… | 明确确认后写入已有方案；提示已知正式／默认引用。该名称的后续读取可能随之改变 |
| 设为当前默认／设为默认 | 单独改变 active；必须先保存草稿。普通 `@active` 使用方在下次解析时采用，正式泰坦的显式方案名不随之切换 |
| 重读磁盘…／重读… | 外部修改后重新读取；草稿未保存时需明确确认丢弃。失败保留现有草稿 |

未保存状态、候选名称、修订、当前默认与生效方式在面板显示。非法文字、范围、整数或字段关系错误会阻止应用／保存；跨台初建保留最近合法样本，错误草稿继续显示并可返回修正，面板内直接切换对象或方案时也须先修正或撤回；左上角返回及专业入口跳转不受此限制，原文按对象／方案／专业视图保留。错误原文保留，提示不随草稿刷新消失，预览失败会定位字段。数字输入精度与箭头步长分别处理，未编辑字段不按显示步长舍入回写。允许范围与原建议范围已分开，详见[实验范围与错误恢复](敌人统一参数与攻击观察.md#实验范围与错误恢复)。

**生效时机**：纯外形即时反馈；兜虫战斗条目用同一完整草稿重建宿主，明确提示“已应用：观察样本已重建”，保留相机与冻结时钟。碰撞盒、局部脚底、根体型和导航代理一起更新；连续改材质／体型及跨台返回不会累乘旧体型。战斗技能仍需重新观察／生成；返回不会把旧运行值写回草稿。当前轮次和已排队补兵保持开局参数。保存候选后还需要明确选用；现有原型场重新生成读取当前默认。正式沉积泰坦读取 `game_config.bosses.sediment_titan.preset`，面板提供“载入正式 Boss 引用”便于编辑当前指定方案。

不同 F6 运行属于不同进程，不会自动共享未保存草稿；结束运行也不保留草稿。需要跨运行保留时显式保存命名方案。跨进程预览的数据快照合同已建立，实际通信和往返工作流尚未接入。

## 保存位置与引用保护

- 定义与基础值继续使用 `data/enemies/` 的七份现有 schema；命名方案与 active 继续写入 `data/enemy_presets/<profile>.json`。
- 新面板默认禁止重名另存。显式覆盖会核对磁盘内容指纹与 schema 指纹；发现外部变更则拒绝覆盖，保留草稿，允许重读或另存。
- 覆盖提示识别当前默认、正式泰坦指定名及 encounter 显式名称引用；不宣称发现所有任意脚本中的引用，也不提供操作系统级多进程文件锁。
- 六物种、泰坦及旧图鉴的身份映射由现有注册表派生；新三种的外形／战斗仍共用各自 `Visual` profile。

## 专业归属与共用导航

视觉只调整体型、外形、材质、纯动作表现；真实技能时序、伤害、攻击移动、个体策略由战斗原型台编辑。视觉默认收起战斗参考，勾选“战斗参考（只读）”或搜索可查看；原型页外形显示只读引用。工具提示说明模型／碰撞、真实投囊／狙击发射点及死亡等待等依赖，不能仅凭原schema分组名称判断归属。

导航在逻辑视口左上角(8,8)，短按钮24像素。调用方节点离树保留，当前专业场景单独活动；返回重新挂回原节点，不重开调用方、不加载active覆盖草稿。新场景和专业视图仍读取同一个Session。该方式本批用于专业页面，不承诺正式实战的投射物／Tween／事件生命周期安全恢复，后者仍属T04。独立开启两个F6进程仍不共享内存草稿。
