# 测试台参数草稿与保存

当前接入战斗原型测试台的既有敌人参数面板，以及视觉测试台中三种纯外形的既有面板。它们使用同一份参数定义、命名方案与草稿服务；没有新增一套游戏数值。跨台导航、暂停拾取和完整技能编辑仍按后续批次实施。

七种敌人的面板现已统一为八分页，并增加“观察本草稿”：单体、固定目标、指定技能重播、范围与实际部位／弹体轨迹、暂停／单帧／慢放。见[统一参数与攻击观察](敌人统一参数与攻击观察.md)及[全部732字段映射](敌人统一参数表.md)。这里的草稿／保存边界继续适用；完整时间轴与冻结姿态即时调形仍未接入。

## 从哪里打开

- Godot 编辑器打开 [战斗原型场景](../../prototypes/combat_lab/combat_lab.tscn)，F6 运行，在程序化敌人行点击“调参”。当前支持六种小怪及沉积泰坦。
- 打开 [视觉场景](../../prototypes/visual_lab/enemy_visual_lab.tscn)，F6 运行，选择爆囊爬兽、棱眼蛛或裂甲兜虫的**纯外形条目**，右侧显示外形面板。它们对应的战斗实体条目目前仍只有观察能力。
- 战斗空间测试台继承已有战斗面板；当前没有新的统一首页或从正式场景暂停点击跳转的入口。
- 敌人配置区采用两行顶部工具栏：标题／已选数量／统计／“?”一行，等级／无敌／敌不死／个体差异／循环一行。说明悬停“?”或相应控件查看；保存提示为空时不占位，非空时显示一行摘要并可悬停看全文。
- 底部“开战／实战陪练／继续／清场／全不选”排在一行，只有暂停战斗时显示“继续”。短按钮保持原动作与保存范围，完整用途在悬停提示中。
- 大部分垂直空间留给敌人列表；七种程序化敌人每行都有“调参”，长名称不挤掉按钮，可滚动到最后一行。战斗空间台左侧也采用三行紧凑的预设／起点工具区。

## 调整与保存

| 操作 | 实际作用 |
|---|---|
| 切对象／方案 | 同一运行进程保留各对象／方案的草稿、修订和候选名称；切回来继续编辑 |
| 搜索 | 按参数名称、字段名与模块定位；战斗面板会跳到首个匹配分页 |
| 撤销／重做 | 修改共享草稿，最多保留 64 步撤销；不写磁盘 |
| 还原草稿 | 恢复该草稿最近载入／保存时的值；战斗面板另可载入 schema 基础值 |
| 保存候选 | 输入新名称并保存；不自动切换当前默认，不改正式 Boss 的指定方案名 |
| 覆盖同名… | 明确确认后写入已有方案；提示已知正式／默认引用。该名称的后续读取可能随之改变 |
| 设为当前默认／设为默认 | 单独改变 active；必须先保存草稿。普通 `@active` 使用方在下次解析时采用，正式泰坦的显式方案名不随之切换 |
| 重读磁盘…／重读… | 外部修改后重新读取；草稿未保存时需明确确认丢弃。失败保留现有草稿 |

未保存状态、候选名称、修订、当前默认与生效方式在面板显示。非法文字或范围错误会阻止提交／切换；数字输入精度与箭头步长分别处理，未编辑字段不按显示步长舍入回写。

**生效时机**：纯外形预览保留已有即时反馈；战斗属性需重新生成对象。当前轮次和已排队补兵保持开局参数。保存候选后还需要明确选用；现有原型场重新生成读取当前默认。正式沉积泰坦读取 `game_config.bosses.sediment_titan.preset`，面板提供“载入正式 Boss 引用”便于编辑当前指定方案。

不同 F6 运行属于不同进程，不会自动共享未保存草稿；结束运行也不保留草稿。需要跨运行保留时显式保存命名方案。跨进程预览的数据快照合同已建立，实际通信和往返工作流尚未接入。

## 保存位置与引用保护

- 定义与基础值继续使用 `data/enemies/` 的七份现有 schema；命名方案与 active 继续写入 `data/enemy_presets/<profile>.json`。
- 新面板默认禁止重名另存。显式覆盖会核对磁盘内容指纹与 schema 指纹；发现外部变更则拒绝覆盖，保留草稿，允许重读或另存。
- 覆盖提示识别当前默认、正式泰坦指定名及 encounter 显式名称引用；不宣称发现所有任意脚本中的引用，也不提供操作系统级多进程文件锁。
- 六物种、泰坦及旧图鉴的身份映射由现有注册表派生；新三种的外形／战斗仍共用各自 `Visual` profile。

## 当前覆盖边界

- 泰坦体型、生命、远距震拳宽度／距离／伤害／起手／出手／收势／冷却、前半招组上限共十个试点字段，已明确模块、单位、生效和观察方法。其余 schema 字段保留现有数值入口，细分归属与即时反馈标为待接入；不是 732 个字段全部效果已验收。
- 当前 `sanctum_creatures.json` 的全部字段已有实战测试台模块归属，但关卡／波次编辑面板、编组投放与组策略仍待 T05／T06；文件外置和字段登记不等于已有可操作入口。
- 编组模板／修订、组实例、成员身份，以及场景“仅本轮选用”目前是纯数据合同。没有实际启用新的组运行器、场景绑定或预览窗口。
- 七种战斗实体的外形重应用与技能形态即时编辑仍待 T02／T03；不因已有数值框就宣称这些能力完成。

自动验证和实施证据见 [同一任务记录](../tasks/实验与调试体系摸底.md) 的 T01 执行结果；用户操作体验仍待验收。

全测试台公共调节入口（含显示／风格、光照／雾、Sky3D／时钟、云／天气／风、声音和公共诊断）已纳入同一任务的T04／T08／T09／T10／T12规划，尚未接入；现有F9／F10的玩家／暂停限制仍未在本次配置列表修复中改变。
