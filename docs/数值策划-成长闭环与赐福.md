# 数值策划：成长闭环 / 生存侧 / 遗迹赐福

> **这份文档补什么**：`docs/数值验收基线.md` 已经把**武器侧**（DPS 曲线 / 敌人血量 / TTK /
> 净杀伤效率 / 狙击契约）做到了可验收的程度。但它有**三块空白**，而这三块正好是"没有数值策划"最痛的地方：
>
> 1. **没有统一的强度单位** —— 所以每加一个东西（赐福、共鸣、Boss、手雷）都只能凭感觉拍。
> 2. **完全没有生存侧** —— 只有"我怎么杀"，没有"我怎么活"。玩家血量全等级恒定、敌人伤害涨 2.68 倍。
> 3. **赐福层没有任何数值** —— 14 个词条的数值全部写死在代码和中文描述里，0 个进配置，且 4 个是空转的。
>
> 配套工具：`_analysis/numerics_progression_model.py`（读 `data/game_config.json`，
> 输出 `_analysis/numerics_model_output.txt`）。本文所有"实测"格都由它复算，可重跑。

---

## 一、口径：先把尺子立起来

**1 PU（Power Unit）= L1 玩家 1 秒的纸面输出 = 140 点伤害。**

任何数值除以 140，就得到"等于 L1 玩家打几秒"。这把尺子一立，拍脑袋就变成了算术：

| 对象 | 点伤害 | PU | 说明 |
|---|---|---|---|
| 近战士兵 血 @L1 | 122 | 0.9 | |
| 重装战士 血 @L1 | 284 | 2.0 | |
| 巨型破坏者 血 @L1 | 702 | 5.0 | |
| 巨型破坏者 血 @L12 | 2704 | 19.3 | 涨到 3.85 倍 |
| 手雷（6s CD） | 95 | 0.7 | |
| 震地脉冲（9s CD） | 55 | 0.4 | |
| 共鸣爆发 100% 蓄力 | 520 | 3.7 | AoE 20m |
| **共鸣爆发 200% 过载** | **2400** | **17.1** | AoE 26m |
| **Boss warden 总血** | **2600** | **18.6** | |
| 一整张图（sanctum 68 敌）总血池 | 5229 | 37.4 | |

**这张表直接暴露了两个致命问题：**

- **Boss 总血 18.6 PU，而共鸣过载单发就是 17.1 PU —— 一次不需要瞄准的 AoE 打掉 Boss 92.3% 的血。**
- **Boss 是常量，玩家 DPS 涨 12~36 倍。** 玩家 L1 无模块打 Boss 要 18.6 秒，L25 满配要 0.5 秒。

## 二、五个断点（都是实测，不是推测）

### 断点 1 —— 模块**双重生效**，隐藏 ×2.95 乘数（最严重）

每个模块层做两件事，而不是一件：

```gdscript
# player_weapon.gd:962  每层 +1 武器等级（抬曲线）
_weapon_level += 1
# player_weapon.gd:1002 / 1012  再乘一次独立倍率
func get_fire_rate_multiplier(...) -> float: return 1.0 + _upgrade_stacks("fire_rate") * 0.08
func get_damage_multiplier(...)   -> float: return 1.0 + _upgrade_stacks("damage") * 0.10
# player_weapon.gd:883 / 1091  实际开火同时乘这两者
return shots_per_second * bonus * get_fire_rate_multiplier()
return base * get_damage_multiplier()
```

满配（8+8 层）：`1.64 × 1.80 = 2.95×`。

> ⚠️ 注意一个容易搞错的地方：**模块层数本身就是武器等级**（`_weapon_level = 1 + 总层数`），
> 所以"L12 且 8+8 满模块"是不可能同时成立的组合。按实际可达的配方复算：

| 玩家状态 | 总层数 | 模块倍率 | 实际 DPS | 基线口径净效率 | **实际净效率** |
|---|---|---|---|---|---|
| L1 开局 | 0 | 1.00× | 140 | 1.00 | 1.00 |
| L12（8 射速 + 3 威力） | 11 | 2.13× | 1990 | 0.70 | **1.49** |
| L25（8/8/8 满配） | 24 | 2.95× | 5138 | 0.68 | **2.01** |

**后果有两层，第二层更严重：**

1. 门槛量的是**纸面曲线**，实际值要高 1.5~3 倍（L25 已越过 2.0）。基线口径那 0.70 本身也不准——
   它只按"同一个敌人变肉"算，没算**图鉴随等级解锁更肉条目**的成分（L1 只有 3 条、L4 起 15 条）。

2. **更根本：这个指标和节奏无关。** 实测表三的"瓶颈"列**每一波都是「出怪」**——
   出怪速率 `1/0.85 = 1.18 只/秒` 才是关卡时长的唯一决定因素。
   所以玩家 DPS 从 140 涨到 5138（**36.7 倍**）**一秒钟的关卡时长都省不下来**，
   它只降低"挨打时长"。基线第五节用了最大篇幅讲究这个指标，但它不是难度曲线。

   换句话说：**真正的难度旋钮是 `spawn_interval` / `max_alive`，强度旋钮只作用在受击压力上。**
   这两件事在现在的配置里是解耦的，而没人写明过。

### 断点 2 —— 出怪正反馈环：杀得多 → 等级高 → 出怪更多

```gdscript
# wave_director.gd:389-396
total += extra_per_level * maxf(float(_weapon_level) - offset, 0.0)   # 7 × max(L-4, 0)
```

而 `_weapon_level` 由**掉落模块**驱动（断点 1）。于是：

| sanctum 波次 | 起始等级 | 敌人数（拾取率 100%） | 敌人数（拾取率 50%） |
|---|---|---|---|
| 1 | 1 | 11 | 11 |
| 2 | 4 | 15 | 15 |
| 3 | 5 | 26 | 19 |
| 4 | 11 | **72** | 23 |
| 合计 | 结束 L23.5 | **124** | 68 |

第 4 波 72 个敌人不是设计，是**环的产物**。而且武器等级完全取决于"玩家愿不愿意回头捡包"——
50% 拾取率收尾 L11，100% 收尾 L24，**同一关的强度方差 2 倍以上**。

### 断点 3 —— Boss 血量是常量

`boss.gd:109` 直接读 `bosses.<id>.health`，**无任何等级缩放**。配合断点 1/2：

| 玩家状态 | 实际 DPS | Boss TTK | 要 60s 需血量 |
|---|---|---|---|
| L1 无模块（开局） | 140 | 18.6s | 8400 |
| L6（约 2+3 模块） | 865 | 3.0s | 51888 |
| L12 验收基线终点 | 956 | 2.7s | 57330 |
| L12 满模块 | 2821 | 0.9s | 169238 |
| L23 100% 拾取率均值 | 4781 | **0.5s** | 286868 |

**Boss 在所有档位都不是战斗。** 另外 4 个 Boss 血量 2600/3000/3400/3800 这个阶梯**没有依据**——
因为每阶段武器等级会重置（`run_state.gd:84`），玩家强度回到同一水位，四场 Boss 应当难度相当。
差异应该放在**行为**上，而不是血量数字上。

### 断点 4 —— 生存侧整块缺失，且方向是反的

`数值验收基线.md` 十二节里**没有任何生存、护盾、承伤、回复的章节**。而实测：

| 量 | 值 | 来源 |
|---|---|---|
| `player.max_health` | **100，全等级恒定，不存在任何成长途径** | `player.gd:253` 是唯一写入点；14 个赐福无一触及 |
| 护盾 | 70，停火 3s 后 35/s 回满 | `game_config.json:439-441` |
| 受击无敌帧 | 0.42s，**所有伤害来源共用一个锁** | `player.gd:806-857` |
| 生命自愈 | 6/s，但 `cap_ratio 0.5` → **只能回到 50** | `game_config.json:443-445` |
| 玩家护甲/减伤 | **不存在** | — |
| 复活/扶起机制 | **本仓库从来没有过**（`视觉迭代日志.md:433` 记的是上游项目，移植时没带过来） | — |
| 敌人伤害成长 | `×(1 + 0.14×等级)` → L12 时 **2.68 倍** | `enemy_spawner.gd:120-122` |

**无敌帧是唯一的承伤天花板**：每秒最多挨 `1/0.42 = 2.38` 次，与场上有多少敌人无关。
所以承伤只跟"单次伤害"走：

| 等级 | 平均单击 | 承伤上限/秒 | 极限存活 | 治疗收入/杀 |
|---|---|---|---|---|
| 1 | 10.4 | 24.7 | **6.9s** | 1.36 |
| 4 | 20.9 | 49.7 | 3.4s | 1.36 |
| 12 | 35.8 | 85.3 | **2.0s** | 1.36 |
| 25 | 60.2 | 143.2 | 1.2s | 1.36 |

**生存窗口随等级缩小 5.8 倍，而输出放大 36.7 倍。基线只算了后一半。**

换成"必须规避多少接触时间"更直观（可持续承伤 = 护盾再生 = 14 点/秒）：

| 等级 | 承伤上限/秒 | 必须规避的接触时间 |
|---|---|---|
| 1 | 24.7 | 43% |
| 4 | 49.7 | 72% |
| 12 | 85.3 | **84%** |
| 25 | 143.2 | 90% |

> 治疗收入 1.36 点/杀，一整图 68 杀 = 92 点；而承伤是 24~143 **点/秒**。
> **治疗与承伤差两个数量级** —— 养不活"挨打换输出"的打法，玩家只能纯规避。
> 这就是"没想法"的根源之一：不管怎么调赐福，生存侧没有可用的加法。

### 断点 5 —— 赐福层完全没有数值

14 个词条，**0 个读配置**。数值全写在中文描述里，而描述与代码有 8 处对不上：

| 词条 | 描述说的 | 代码实际 |
|---|---|---|
| `overload_core` | 伤害 +30% | `× 1.35`（+35%） |
| `timewarp` | 2.2s → 4.2s | `2.5` → `4.5` |
| `chain_lightning` | 5 米 | `6.5` 米 |
| `desperate_will` | 血量 <35% 时 +40% | `hp < hp×0.35` —— **恒假，永远不触发** |
| `resonance_amplification` | 溢出空间提升 | `_overflow_cap` 从 200 **降到 195** |
| `shield_overload` | 自愈延迟 −0.8s | 未实现 |
| `reaper_echo` | 返还 35% 能量 | `_energy = refund`（**赋值**，不是返还） |
| `rapid_cycler` | +12% / −20% | 按**乘法**叠加（2 层 = ×1.2544 / ×0.64） |

**4 个词条是空转的**（选了没有任何效果）：

| 词条 | 稀有度 | 状态 |
|---|---|---|
| `armor_pierce` | RARE | **全项目 0 处实现**，只在目录里 |
| `resonance_burn` | **LEGENDARY** | 只创建一个空 `Node3D`，5 秒后销毁；`radius` 参数未使用，无伤害 |
| `desperate_will` | COMMON | 阈值自比较，恒假 |
| `incendiary_rounds` | COMMON | `apply_hit_effects()` **全项目无调用方**，死代码 |

以及一个 **`refresh_perks()` 非幂等 bug**：`resonance.gd:74-76` 用 `+=` 而不是重算，
而 `player.gd:1129` 每次选**任何**赐福都调它一次 —— 只拿 1 层 `resonance_amplification`，
选 4 次赐福后 `_max_energy = 100 + 30×4 = 220`。

**稀有度没有任何强度标准**：`resonance_burn`（LEGENDARY，空转）和 `incendiary_rounds`
（COMMON，若接线则 +35% 总伤害 = 最强的那个）定价正好反了。

## 三、设计目标（当前完全缺失，必须先声明）

没有目标就没法判断"调到多少算对"。以下是我建议的目标，**都是可验收的数字**：

| 指标 | 建议目标 | 现状 | 依据 |
|---|---|---|---|
| 一张图时长 | **3–3.5 分钟** | ~2.2 分钟 | 4 波 + Boss 的节奏 |
| Boss 战时长 | **45–75 秒** | 0.5–18.6 秒 | 需要走位与弱点利用 |
| 武器等级终点（单图） | **L12** | 11–24（随拾取率） | 与基线曲线表对齐，且消除方差 |
| 净输出增长 L1→L12 | **≤ 8×** | 12.6–14.6× | 沿用基线"不碾压"意图，但用正确口径 |
| 生存窗口衰减 L1→L12 | **≤ 2×** | 5.8× | 与输出增长对冲 |
| L12 必须规避的接触时间 | **≤ 70%** | 84% | 高等级仍可站桩输出一部分 |
| 赐福强度 | 按稀有度入预算（见第五节） | 无标准 | |

## 四、数值设计：成长闭环

### 建议 4.1（核心）—— 武器等级改为**确定性推进**，模块只做特化

这一条同时修掉断点 1、2 和等级方差。**理由是：靠掉落驱动的强度增长，天然带 ±50% 方差**
（拾取率 50% → L11，100% → L24）。数值策划的第一原则是"强度增长要可控"。

```jsonc
// 新增：等级由波次确定性供给
"weapon": {
  "max_level": 12,
  "levels_per_wave_cleared": 3,     // 4 波 -> L1→L4→L7→L10→L12(封顶)
  "upgrades": {
    "fire_rate": { "per_stack": 0.04, "max_stacks": 8, "apply_to_sniper": true  },
    "damage":    { "per_stack": 0.05, "max_stacks": 8, "apply_to_sniper": false },
    "magazine":  { "capacity_per_stack": 5, "reload_per_stack": -0.02, "max_stacks": 8, "apply_to_sniper": false }
  }
}
```

- `player_weapon.gd:962` 的 `_weapon_level += 1` **删除**（改由 `wave_director` 在 `_finish_wave()` 里推进）。
- 效果：满配额外乘数从 `2.95×` 降到 `1.32 × 1.40 = 1.85×`；等级终点锁定 L12；**与拾取率解耦**。

### 建议 4.2 —— 断开出怪反馈环，改成纯波次线性

```jsonc
"spawn": { "extra_enemies_per_level": 0 }        // 原 7
"arenas.definitions.sanctum.wave": {
  "base_enemies": 22,        // 原 11
  "growth_per_wave": 6       // 原 4
}
```

→ sanctum **22 / 28 / 34 / 40 = 124 敌**（总敌人数与现在持平，但**线性、无第 4 波尖峰**）。
出怪时间 `124 / 1.18 = 105s`，加 3×6s 波间 + 4×2.2s 特写 = **132s ≈ 2.2 分钟**，加 Boss 60s ≈ **3.2 分钟** ✓

> 若你想保留"等级越高越挤"的手感，把 `extra_enemies_per_level` 取 `1.0` 而不是 0：
> L12 时每波 +8 个，仍不会失控。

### 建议 4.3 —— Boss 血量改用公式反推

```
boss.health = 玩家在 Boss 出场时的预期实际 DPS × 有效输出秒数
```

- 玩家在 Boss 出场时 ≈ **L12**（4 波清完），模块约 4+4 层
- 实际 DPS = `955.5 × (1+4×0.04) × (1+4×0.05) = 955.5 × 1.16 × 1.20 ≈ 1330`
- 目标 TTK **60 秒墙钟**，走位/闪避占一半 → 有效输出 **30 秒**
- → **`bosses.warden.health: 2600 → 40000`**（×15）

四个 Boss 应当**血量接近**（因为每阶段武器等级重置，玩家强度回到同一水位），
差异放在行为上。建议：`warden 40000 / breaker 40000 / colossus 40000 / sentinel 40000`，
用 `behavior`（charge/slam/barrage）和 `weak_point_ratio` 区分难度。

> ⚠️ 这是**数量级**判断（×15），不是精确值。TTK 的"一半时间在走位"必须靠试玩校准。

### 建议 4.4 —— 共鸣爆发接回武器曲线（顺手清死键）

现状 `resonance.gd:293-316` **硬编码** `520 / 2400 / 1200`，而配置里的
`resonance.burst_damage_base` 与 `burst_damage_per_energy` **读取了但从不使用**（死键）。

```gdscript
# 建议：爆发 = 玩家当前输出的 N 秒等效，永远不喧宾夺主
base_dmg = curve_dps(weapon_level) * engaged_seconds(ratio)   # ratio 1.0 -> 2.0s, 2.0 -> 6.0s
```

这样 L12 时 100% 档 = `955 × 2 = 1911`，200% 档 = `955 × 6 = 5733`；
Boss（40000）吃一次过载 = 14% —— 合理，而不是现在的 92%。
并且把 `burst_damage_per_energy` 这个死键**删掉或接上**（不要留着）。

## 五、数值设计：遗迹赐福（"完全没想法"的那块）

### 5.1 单位与预算

**1 BU（赐福强度单位）= 等效持续输出 +0.1 PU/s = +14 点/秒。**

| 稀有度 | 强度目标 | 出现权重（现行 `roll_three`） |
|---|---|---|
| COMMON | 2–3 BU | 全部 14 个里 7 个 |
| RARE | 4–6 BU | 5 个 |
| LEGENDARY | 8–12 BU | 2 个 |

**叠加规则（新增，当前完全缺失）**：同一词条最多 3 层，第 2、3 层收益 **×0.6 递减**。
理由：`roll_three` 不排除已拥有词条，而 `rapid_cycler` 目前是**乘法**叠加
（2 层 = 速度 ×1.2544、翻滚 CD ×0.64），会失控。

### 5.3 每一处数值改动的依据

| 词条 | 改动 | 依据 |
|---|---|---|
| `resonance_amplification` | **重做**：`+30 能量上限` → `爆发伤害 +12%/层` | 原效果**是负收益**：`ratio = 能量/上限`，抬上限会稀释爆发；且它把 `_overflow_cap` 从 200 覆盖成 195 |
| `fury_charge` | 保持 +50%，进配置 | 数值与描述一致，是一战合格 COMMON（≈3 BU） |
| `phantom_dodge` | 保持 +100%，进配置 | 完美闪避 20→40 能量，RARE 合理（≈4.4 BU） |
| `reaper_echo` | 修 `_energy = refund` → `+=`，或明确定义为"重置到 35%" | "返还"写成赋值，玩家剩余能量被吞掉 |
