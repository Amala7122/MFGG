# 寂石圣所（Sanctum Arena Study）

2026-10-27。用于回答“圣所是否可以重做成一个真正的关卡”的**编辑器优先**试作场景。
它不是主场景，不接战斗、波次、导航或天气系统；先用于步行预览与空间/构图判断。

场景名定作 **寂石圣所**：寂石就是主祭坛上的那颗圣晶体，整个修士院建筑群是围绕它长出来的。当前方向是 **完整圣所、遭袭后仍由教团据守和修缮**，不是全废墟，也不是 pristine 教堂。

> **2026-10-27 总平面修正（待执行）**：当前场景仍把修士院、食堂、客房塞在同一圈主墙内，从外面读成“一栋大建筑”。用户要的是**主教堂 + 真正独立的附属建筑群**；下一步会拆/迁移这些内嵌功能，改为主教堂 + 西侧独立回廊院 + 东侧服务院 + 南门外门村，而不是继续在现有墙里加房间。详见[任务记录](../../docs/tasks/sanctum_arena_redesign.md)。

## 打开与预览

- 在编辑器中打开 `sanctum_arena.tscn`，按 **F6** 运行。
- 预览角色：`WASD` 移动、`Shift` 冲刺、`空格` 跳、左键锁定视角、`Esc` 释放、`R` 回到起点。
- 场景根下 `Markers/` 有 `Camera_Approach`、`Camera_Court`、`Camera_Nave`、`Camera_Altar`、`Camera_Overview` 等空标记，可直接把编辑器相机对过去。

## 布局

- **南侧仪式道（约 24 m）**：石铺、低护墙；两侧是**香客客房**与**马厩/库房**，把入口做成有前庭的小建筑群；尽头是南门。
- **南门**：双**钟塔** + 山花 + 玫瑰窗 + 门楣浮雕 + 打开的木门；门内两名守卫、临时武器架、带箭的盾牌。不再用城垛、箭孔或铁闸。
- **上层回廊（0 m）**：环绕下沉庭院的平台，西侧有完整廊顶，东侧中段塌落。南、北两端各有侧门，接南侧岩台与后侧庭院；中央门楼两侧仍是前庭，不能直接横穿塔楼。
- **下沉庭院（-1.2 m，40 × 30 m）**：中央干涸喷泉/断柱、倒柱、低墙、长凳、圣像、碎石与苔痕；四边是挡土墙与扶手。
- **内门（z=-4）**：更高的双塔门楼、山花、浮雕与玫瑰窗；两翼各有 4 m 侧门，直接通进中殿两侧庭院；门内有守卫。
- **中殿（z=-4…-36，28 × 32 m）**：双排圆柱、木梁、平顶 + 外观双坡屋顶、祭坛上方天光洞、高坛、**主祭坛上的单根六棱圣晶体**、**鲸形圣徽**、六支对称蜡烛、亚麻台布与深红前帷、长凳、倒塌柱与碎石；高坛前有跪凳和祈祷的修士；两侧各开两道门进庭院。
- **主祭坛圣徽**：黑玄武岩鲸形浮雕嵌在背光雪花石圆盘上，外圈是整石雕出的圆窗框、鎏金铜带，225° 石缝上有遭袭后补的铁锔。旧的蓝玫瑰窗、金十字、高坛金环与圣晶外置金环已撤。圣徽在 `Sigils`/`WhaleSigil` 组里，可直接在编辑器里选中/换材质；是场景节点，不是运行时光效。
- **两侧回廊院（garth，x=14…30 / -30…-14）**：不是两块空地，而是**修士生活区**：
  - 西侧 **修士院**：两层，底层议事厅/缮写室/病房，上层宿舍窗；议事厅门廊带钟，缮写室有书桌、书册和缮写修士，病房有床和医护人员。
  - 东侧 **食堂/厨房院**：两层，底层厨房/食堂/地窖；厨房有炉灶、锅、柴、厨师；食堂有长桌、长凳、碗和读经修士；地窖有酒桶、粮袋和司库。
  - 两院内侧是单坡柱廊，四周围合草庭、水井、菜畦/药草畦、晾衣绳、鸡、长凳、圣像；后廊接墓地。
- **后廊/墓地（z=-36…-40）**：墓碑、石十字、骨龛、哀悼的修士，以及后廊祭台。
- **东侧坍塌与修缮**：上层回廊东段保留坍塌口，临时木撑、脚手板、短梯、拒马、带箭盾牌；泥瓦修士在修，守卫在守。
- **侧龛**：西侧红祭坛、东侧黄祭坛的小礼拜堂，入口开向上层回廊，走道从 4 m 加宽到 6 m；两侧各有中段步梯下庭院。

设计意图：把老地图“大草坪 + 远处装饰门”改成**有门槛、有高低两层、有多个入口和环路、有明确终点**的紧凑圣所。庭院是低层空间，回廊是高层观察/侧翼路线，中殿是高坛舞台的候选；两侧回廊院负责“有人真的在这里生活、祈祷、经营、修缮、守护、战斗”的证据。

## 流线：不再只有南门一个口

- **南门**：主入口，接仪式道。
- **南墙两侧门**（x≈±20）：从上层回廊直接出到**南侧岩台**，沿岩台可到另一侧、再到仪式道/南门。
- **东/西侧门（postern，z≈26）**：从上层回廊出到东/西岩台，沿岩台向南接南侧岩台。
- **内门两翼侧门**（x≈±24）：从上层回廊进西/东庭院；穿过后廊可从另一侧出来，**不需要回中庭**。
- **中殿侧门**（x≈±14，z≈-10 / -26）：中殿与两侧庭院互通；高坛不再是死胡同。
- **中央门楼前庭**仍是收束空间，不能横穿塔楼；这是有意的门槛，不是唯一通路。要从一侧回廊到另一侧，走**南侧岩台**或**后侧庭院/后廊**。

## 宗教化改造

- 城垛、箭孔、铁闸撤掉；入口改成**钟塔 + 尖顶 + 山花 + 玫瑰窗 + 门楣浮雕 + 十字**。
- 中殿加外观双坡屋顶与两端十字；内部高坛改成**鲸形圣徽 + 圣晶遗物**，不再用旧玫瑰窗/金十字/光环。
- 石材从冷灰改成**暖石灰**；庭院与后廊加**柱廊、骨龛墙、圣像、柏树**。
- **圣晶体**：只保留**主祭坛**一根六棱晶体（柱身 + 锥尖，深色石座 + 金箍、冷光），不再做簇状，也不在庭院/水井/小礼拜堂重复放置。它在 `Crystals` 组里，可直接在编辑器里选中/移动/换材质；是场景节点，不是运行时生成物。
- 雕像重做：窄身长袍、垂褶、合手、面纱/光环/天使翼；去掉了原来像茶壶的“手臂 + 尖帽 + 长柄”剪影。
- 高坛不再立十字架；十字保留在屋顶两端、钟塔尖顶、门楼封印和墓地。鲸形圣徽是寂石圣所自己的标志。

## 主祭坛圣徽（2026-10-28）

用户给的参考图是一只黑鲸形标志；主祭坛后面的标志必须按它来做，而不是继续用玫瑰窗/十字。

- **轮廓**：参考图 75×68 PNG，sha256 `ab001810d5da763d0406dad5f5fb69890cc5d43508b181957d610ab08b4360ee`。在 4× 放大灰度上做 marching squares（0.5），再用 RDP 0.20/0.16 px 简化，归一化到宽 1.0；外环 57 点、腹部 28 点、眼斑 14 点。
- **数据**：[sanctum_sigil_paths.json](../../assets/generated/valley/sanctum_sigil_paths.json)。构建脚本 `_whale_sigil()` 读取后挤出；缺失/无效会直接让构建失败。参考图本身没有进工程。
- **立面**（由后到前）：整石圆框（表面刻 16 道浅分缝，225° 裂缝 + 铁锔）→ 背光雪花石圆盘（自发光 0.42，暖白）→ 鎏金铜带（内 2.02/外 2.09 m）→ 玄武岩鲸形浮雕（宽 3.21 m、凸 0.09 m）→ 腹部/眼斑雪花石嵌片（扩边 0.012 m、凸 0.02 m）。
- **为什么这样做**：雪花石透光，背光石是真实工艺；玄武岩适合浅浮雕；黑鲸+白留白正好是参考图的读法。石环的浅缝是整石表面刻线，不是 24 块深槽楔石（第一版深槽会读成齿轮，已弃用）。
- **灯**：不再有从殿内打来的无来源射灯；只有 `Hall/WhaleSigil/AlabasterSpill` 的 0.5 能量暖色 Omni，负责照亮石框和浮雕侧壁，解释为背光石溢出的光。
- **高坛陈设**：亚麻台布（前垂 10 cm、折边/压痕）、深红前帷（金线滚边）、六支 3+3 对称蜡烛（黄铜接蜡盘）、圣晶石座（金箍，晶体插入 0.10 m）、祭坛基座与三级台阶压边。高坛后墙脚下原先的大石块已移除；遭袭痕迹留在东回廊/中殿侧廊。
- **细节理由**：石环=圆窗承重框；分缝=整石刻线；铁锔=遭袭后修补；雪花石=透光石；玄武岩=黑石浮雕；金带=鎏金铜收边；台布/前帷=祭坛使用与礼仪色；六烛=礼仪对称；石座=圣物插座；压边=石构件防踩损收边。

## 生活、祈祷、经营、修缮、守护、战斗

场景里的“人”都是**静态低多边形模型**，不接 AI、动画或战斗；它们用于让空间读成“真的有人住在这里”。

- **人**：南门守卫、内门守卫、高坛跪祷修士、议事厅先导、缮写室修士、病房医护、厨房厨师、食堂读经/用餐修士、地窖司库、园丁、晾衣修士、井边修士、泥瓦修士、坍塌口守卫、香客、医院修士、马夫、墓地哀悼者。
- **生活/经营**：修士院宿舍窗、议事长桌、缮写桌/书册/书架、病房床铺、厨房炉灶/锅/柴、食堂长桌/碗、地窖酒桶/粮袋、菜畦/药草畦、鸡、水井、晾衣绳、香客客房、马厩/干草/水槽/骡子。
- **祈祷**：主祭坛跪凳、跪祷修士、圣晶、鲸形圣徽、六支烛台；议事厅门廊的钟与十字；后廊墓地石十字与哀悼者。
- **修缮/守护/战斗**：东侧坍塌口的木撑/脚手板/短梯/拒马/带箭盾牌，泥瓦修士与守卫；南门武器架、带箭盾牌和守卫；内门守卫。没有尸体和血腥表现。

## 编辑器优先

- 场景里所有墙、台阶、柱、门、雕像、火盆、碎石、屋顶、灯光都是**普通节点**；可以直接选中、移动、旋转、复制、改材质。
- 不依赖 `world_map_builder.gd`、`terrain_field.gd`、`valley_art.gd`、`world_decor.gd`、`grass_field.gd`、`field_cover.gd` 这些运行时生成器。
- 唯一运行脚本是预览角色 [`preview_walker.gd`](../../scripts/preview/preview_walker.gd)，只负责走动和鼠标视角，不参与地图生成。
- 远景复用了已烘焙的 `assets/generated/valley/sanctum_mountains.res` 与 `sanctum_art.scn` 中的瀑布/落石/远路；近景树林是本场景自己的静态网格。

## 重新生成

`tools/build_sanctum_arena.gd` 是一次性构建工具，不是运行时脚本：

```powershell
Godot_v4.7.2-stable_win64_console.exe --headless --path . --script res://tools/build_sanctum_arena.gd
```

它会**覆盖** `sanctum_arena.tscn` 和 `preview_walker.tscn`。一旦开始在编辑器里手工修改场景，就不要再无条件重跑；先备份，或把构建脚本当作只用于生成初版的工具。

构建还会读取主祭坛圣徽的轮廓数据 [sanctum_sigil_paths.json](../../assets/generated/valley/sanctum_sigil_paths.json)。这份 JSON 是从用户参考图描出来的归一化闭合多边形；缺失或无法解析时构建会直接失败，不会生成一个空圣徽。参考图本身不在工程里；如果要改圣徽形状，先用同样的 marching-squares + RDP 流程重出 JSON，再重建。

高坛特写可以单独跑：

```powershell
python -B tools/run_probe.py tools/probes/sanctum_sigil_review.gd --graphics --task sanctum_sigil_review
```

（若 `project_hygiene` 因既有 docs 链接失败而挡住 `run_probe.py`，复用 `run_acceptance.isolate_project` / `run_check` 跑同一探针；隔离与无焦点约定不变。）

## 亮度与颜色

首版在编辑器里整体偏暗，已按反馈把 `WorldEnvironment`（天空、环境光、曝光、雾）和石材亮度整体抬回可读区间；外侧原来的整块深色地台改成窄岩台 + 山体远景，避免编辑器里看到一大块桌面。

- 若只想让室内更亮：先调 `Lights/HallFill` 的 `light_energy`、`Hall/Roof` 的面板数量，或 `Hall/SideWindow*`。
- 若想把整体压回更阴冷的氛围：调 `WorldEnvironment` 的 `tonemap_exposure`、`ambient_light_energy`、`Sun` 的 `light_energy`，不要再来回改石材颜色。
- 主祭坛圣徽的亮度由雪花石自发光与 `Hall/WhaleSigil/AlabasterSpill` 决定；想更暗/更暖就调 `alabaster` 的 `emission_energy_multiplier`（当前 0.42）和溢光的 `light_energy`（0.5），不要给圣徽再加第二个射灯。
- 编辑器如果还显示旧暗版本，关闭 `sanctum_arena.tscn` 标签后重新打开；不要直接保存旧副本覆盖新文件。

## 没有接入的东西

- 敌人、波次、出生点、导航烘焙、战斗、Boss、掉落、升级、结算。
- 正式天气/时间系统；当前是固定的晴天/薄雾预览环境（程序化天空、雾、暖色火盆/冷色天光）。
- 性能预算与正式美术定稿；场景约 13.7 MB、约 1442 个节点，几何是 blockout 级别。
- 部分屋顶、木梁、窗帘、烛台和远景树没有碰撞；这是预览场景，不是可出货碰撞合同。
- 两侧回廊院的建筑、家具和人是静态 blockout；没有 AI、动画、交互或叙事文本。
- 圣晶体目前是静态发光体/灯，不是可拾取、可摧毁或可充能的目标；没有战斗语义。
- 鲸形圣徽、台布/前帷、蜡烛与石座都是静态几何；圣徽没有可破坏、可拾取或可充能语义。

## 已知取舍

- 中殿内部仍是平顶，外观加双坡屋顶；祭坛上方天光洞只覆盖部分屋顶，雨水/天空关系以后要再统一。
- 中央门楼前庭不能直接横穿塔楼；侧门/南岩台/后廊是绕行路线。若希望回廊正中央也能横穿，需要把门楼塔基改成骑楼或加天桥，但这会削弱入口门槛。
- 两侧回廊院是 blockout：建筑外壳、门廊、室内家具、人物都有，但细部、材质分区和上层宿舍内部还没做。
- 人物是静态模型，不会走动、祈祷动画或战斗；它们只负责“这里有人”的读感。
- 东/西岩台只有约 3 m 宽，侧门是窄门；适合“侧门/绕后”的战斗路线，不适合大部队通行。
- 西/东礼拜堂仍是静态小房间，没有奖励或交互；走道已加宽，但东侧塌落段仍故意保留缺口。
- 入口钟塔偏矮胖；如果继续做美术，优先拉高塔身、收窄塔宽，而不是再加装饰。
- 中央喷泉是干涸的断柱/碎像；如果以后要放 Boss 或目标物，优先改这里而不是再加一个新地标。
